## Findings

- **[MAJOR] N1 — Remote-open “phone stays on terminal” is not guaranteed by the stated mechanism, and A12 is too weak.** `design.md:208-213` offers “new non-activating create variant **or** suppress `pendingBrowserFocusPageIdRef`”. The current create uses `activate: true` and sets the pending ref (`mobile/src/session/use-mobile-session-content-create-actions.ts:115-127`), which is what switches the phone (`mobile/src/session/mobile-session-tabs-accepted-effects.ts:28-36`). Suppressing only the ref is insufficient: the host publication passes the caller through `applyMobileSessionTabNavigation`, which moves the caller’s own selection for **any** `navigation` target when `clientNavigationId` is present (`src/main/runtime/browser-tab-create-publication.ts:130-149,237-253`; `src/main/runtime/orca-runtime-close-structured-agent-session-tab.ts:224-251`). A reconnect, startup, or a null `selectedSessionTabIdRef` can then land on the browser (`mobile/src/session/active-session-tab.ts:27-36`; `mobile/src/session/use-mobile-session-tab-application.ts:206`). The existing `activate: false` path (`browserTabCreateTakesFocus`, `src/main/runtime/browser-tab-create-publication.ts:143-158`) already suppresses host and caller focus, but the design never names it. If the product wants the desktop tab focused, no current target focuses only the host while leaving the caller alone; that needs a host-side change and capability gate. **Impact:** the core “phone stays on terminal” promise can fail while A12 passes, because A12 only asserts that the client ref is unset. **Fix:** choose and specify `activate: false` (desktop does not focus) or a new host-side focus-host-only path; do **not** present “suppress the ref” as an equivalent alternative. Define the capability source: `client`/`connState` plus host-status `statusPending`/`statusReadable` (`mobile/src/transport/host-status-gates.ts:11-27,91-105`), not screencast and not an unspecified “callable”. Make A12 assert the `browser.tabCreate` params and that applying the caller-projected session tabs leaves the active tab on the terminal, plus a reconnect case. Update TL-T4/T4A.

- **[MAJOR] N2 — Legacy preference vs new “remember” value cannot both work on one key; switch-off semantics are untested; preselection is undefined.** `design.md:208` says every user, including users with stored `orca-browser`/`phone-browser`, sees the sheet on first click, and `design.md:226-237` says a “remember” choice writes the preference. But there is one key and one enum (`mobile/src/storage/preferences.ts:254-270`), one initial state `'orca-browser'` (`mobile/src/session/use-mobile-session-screen-state.ts:46-47`), and an async load (`mobile/src/session/use-mobile-session-preference-focus.ts:46-48`). A legacy stored `orca-browser` must be preselection-only (A20/A21) while a newly remembered `orca-browser` must direct-route (A8); the same bytes cannot mean both. The action table also never says a write requires the Remember switch to be on, and there is no case for “switch off + Open” or a definition/rendering of “preselection/highlight”. The prototype states 01/02/11 have no preselection visual. **Impact:** A8, A20, and A21 cannot all be correct, and an implementer can silently make the first Open action a permanent preference with the switch off. **Fix:** introduce a versioned key (e.g. `orca:terminalLinkOpenMode:v2` with `ask|phone-browser|orca-browser`) and a one-time legacy read that supplies the preselection then writes `ask`; or add a separate `terminalLinkRemembered` marker. Make the action×switch table explicit: switch off → no write; switch on + Open → write; switch on + Copy/Cancel → no write; write failure → toast, action still runs, next click asks. Initialize state to `ask` until load completes. Add A18 switch-off, A19, A20 preselection rendering, A21 async, and update `preferences.test.ts:477-507` and `browser-settings-screen.tsx:14-24`.

- **[MAJOR] N3 — End-exclusive coordinates are not applied to the drag/selectAll/eviction producers, and there are no unit assertions for them.** `design.md:263-278` names the model and the seed pipeline, and TL-S3 (`tasks.md:76`) names `syncSelectionHandleToViewportPoint`, `selectAll`, etc., but does not define the producer conversion. `syncSelectionHandleToViewportPoint` still assigns the tapped cell directly to `focus` (`mobile/src/terminal/document/selection-overlay.ts:70-87`); with an end-exclusive `focus`, an end-handle drag to cell N would exclude N unless it maps N→N+1, and a start-handle drag needs the opposite. `selectAll` still sets `focus.col = cols - 1` (`mobile/src/terminal/document/host-message-router.ts:123-138`), which is one short for end-exclusive. Eviction mutates `anchor/focus` rows (`mobile/src/terminal/document/selection-state-and-eviction.ts:54-73`) and is not in TL-S3; the selection type is in `mobile/src/terminal/document/document-scope.ts:151-157`. Test B17 is a device case; there is no unit test for drag endpoints, selectAll, eviction, or end-of-line, so an off-by-one implementation can pass G1–G18 (seed only). **Impact:** handle dragging or Select All can be off by one while the seed is correct; the “one coordinate model end-to-end” requirement is not met. **Fix:** define start handle → cell (snap left), end handle → cell+1 (snap to glyph end when the touch lands on a continuation cell), `selectAll` → `cols`, and update eviction/type. Add `selection-range.test.ts`/`selection-overlay.test.ts` (or equivalent) asserting start/end drag, wide-char halves, `endExclusive.col === cols`, multi-line, selectAll, eviction, and `term.select`/model/copy together. Also fold in the clamp bug: `design.md:276` uses `width(lastCell)`; for a wide-char continuation `getWidth() === 0`, so the handle sits on the glyph’s left half. Use the glyph start’s width or clamp the `endExclusive` x to the viewport edge.

- **[MAJOR] N4 — Tokenizer atomicity is still broken for the Chrome-74 fallback and for `WORD_RE` punctuation words.** `design.md:282-285` requires URL/path atomic spans, glyph atomicity, and preservation of `._/:@~+=?&#%-`, but the fallback in `design.md:143-147` only defines `[A-Za-z0-9_]+` and CJK runs. Fullwidth `ＡＢＣ１２３` is neither, so G15 (`test-plan.md:152`) cannot pass without `Intl.Segmenter`, and G20 explicitly requires G1–G17 to be unchanged when Segmenter is absent. Separately, the existing `WORD_RE` (`mobile/src/terminal/document/selection-range.ts:7`) treats `foo-bar`, `key=value`, `a@b.com`, `C++`, `100%`, `a#b` as one word; `Intl.Segmenter` splits all of them (verified), and the fallback’s punctuation boundary splits them too. §7.2.4 only states the constraint, and G22 only covers URL/path, so long-press copy can regress on both modern and old WebViews. **Impact:** G15/G20 fail; existing copy behavior for punctuation-joined words regresses. **Fix:** define one post-merge rule for both Segmenter and fallback that joins `\p{L}\p{N}` with the legacy punctuation set (with sane leading/trailing trimming), plus a fullwidth alphanumeric class/merge; add exact vectors for `ＡＢＣ１２３`, `foo-bar`, `key=value`, `a@b.com`, `C++`, `100%` under both “Segmenter present” and “Segmenter deleted”.

- **[MAJOR] N5 — `mailto:` is in the design matrix and test plan but has no detector and no implementation task.** `design.md:214-224` says `mailto:` opens locally, and `test-plan.md:128` (A16) expects local open/simplified sheet. But text URL detection only matches `https?://` (`mobile/src/terminal/terminal-webview-url-tap.ts:1-12`, `mobile/src/terminal/document/url-tap.ts:5-12`), OSC links only resolve http(s)/file (`mobile/src/terminal/document/osc-link-tap.ts:84-93`), the path regex does not match `mailto:` (`mobile/src/terminal/document/path-tap.ts:28-33`), and `surface-tap.ts:18-55` has no mailto branch. The only mailto task is TL-T10, a test (`tasks.md:66`). **Impact:** A16 cannot pass; a `mailto:` tap falls through to a mouse click/tap. **Fix:** either add a mailto matcher/notification (with length and scheme validation) and an implementation task, or mark mailto out of scope and remove the local-open expectation from A16. Add the routing test.

- **[MAJOR] N6 — Selection task order still has an off-by-one intermediate, and the missing producer tasks are still missing.** `tasks.md:76-84` orders `TL-S7 → TL-S3 (end-exclusive) → TL-S1 → TL-S2 → TL-S4 (seed rewrite)`. The current seed sets `focus` to the inclusive last cell (`mobile/src/terminal/document/selection-range.ts:26-40`); after TL-S3 changes `applyXtermSelection` to end-exclusive but before TL-S4 rewrites the seed, every seed selection is one cell short. The same intermediate applies to drag/selectAll/eviction (N3), which are not in TL-S3’s file list. **Impact:** each task/PR can be locally green only by carrying temporary conversions, or the intermediate state is broken and hard to bisect — the same class of problem the prior M12 raised for the link tasks. **Fix:** make TL-S3 own every producer (seed, drag, selectAll, eviction, `document-scope.ts`) or merge S3+S4 into one change; explicitly require the existing selection tests to be updated in that change; add the missing files/tests to the task rows.

- **[MAJOR] N7 — CJK merge for runs longer than 6 is not deterministic, and the fallback can select an entire 7+ character run.** `design.md:246` says adjacent CJK tokens merge, max 6; `design.md:150-151` says a single CJK character extends 2–6. It does not say which 6: expand left first, right first, or around the tap; whether to split a token to reach 6; or what to do when the fallback CJK regex yields one token longer than 6. `test-plan.md:147` (G10) only covers 4 characters, and G19 (`test-plan.md:168`) has no exact vector. **Impact:** a wrong implementation selecting the whole run (fallback) or a different 6 passes every case. **Fix:** define the merge start/direction and the over-6 rule (e.g. start at the tapped token, alternate left/right or left-first, stop before exceeding 6; fallback chunks a long run into <=6-char windows). Add exact vectors for `中华人民共和国万岁` (tap 人民) and a 7-character fallback run with expected cells/`term.select`/copy.

- **[MINOR] N8 — AC→case mapping has wrong and incomplete IDs.** `test-plan.md:109-117`: AC1 lists A1–A3/A6–A9/A12–A18 but omits A19–A29 (remember failure, legacy preference, initial state, URL summary, HTTP/loopback, keyboard, a11y, folder, OTA, failures); AC2 lists G1–G8 but omits G14–G18 (NFD/fullwidth/wrap/end-of-line); AC4 cites G12 (a URL geometry row) as the selection-model case; the “old WebView fallback” non-goal cites G14 (NFD) instead of G19–G21. **Fix:** map AC1→A1–A29, AC2→G1–G18, AC3→G9–G11, AC4→G1–G18 plus the drag/selectAll tests, AC5→R1–R9, and the fallback non-goal→G19–G21.

- **[MINOR] N9 — Prototype cell annotations do not match the rendered lines.** Selection states 02–06, 08–09, 11–12 annotate bare-vector spans (`terminal-selection.html:229,263,297,331,368,404,438,472,506,541,575`) while the rendered lines include a prompt/command/hash/prefix (`❯ echo `, `a91f2c4 `, `→ 下一步: `). For example `terminal-selection.html:229` says tap cell 3 / span `[0,4)`, but the rendered `❯ echo 中文abc` puts 中文 at cells 7–10; `:331` says `&` at 14 while the rendered line has the prefix. The visual tap dot is correct, but the `term.select` annotation is not. **Fix:** either render the bare test-vector line or state explicitly that the numbers are vector-relative and adjust them to the rendered line; test-plan G1–G18 should remain the authoritative coordinates.

- **[MINOR] N10 — The 500 ms hold state omits the Copy/Select All menu, while the implementation shows it immediately.** `terminal-selection.html:193-205` shows the overlay/handles only; state 12 (`:576-591`) shows the menu. `enterSelect` activates the overlay and `repositionOverlay` positions the menu pill immediately (`mobile/src/terminal/document/selection-range.ts:111-118`, `mobile/src/terminal/document/selection-overlay.ts:15-68`). **Impact:** the prototype is ambiguous about whether the menu appears at 500 ms or on release. **Fix:** show the menu in state 01 (or state a deliberate “menu on release” rule and implement it). Keep the 500 ms timing.

- **[MINOR] N11 — Keyboard restore is circular/contradictory.** `design.md:295` says “取消后按设计恢复或保持收起”, and A25 says “符合设计”; `terminal-link.html:589,600` says “Focus returns to the terminal when the sheet closes”, but the page script’s `closeAll` (`terminal-link.html:792-794`) only removes classes; it never restores focus or the keyboard. **Fix:** choose one policy — restore the pre-open keyboard state (reopen if it was open, stay closed if it was not) or always stay closed — and test both the open-before and closed-before cases. Update the prototype or its caption.

- **[MINOR] N12 — `snapToGlyphStart`’s “or empty chars” can misclassify a legitimate blank cell.** `design.md:260` uses `getWidth() === 0 || empty chars`. xterm’s null/blank cells can have `getChars() === ''` with width 1 (`mobile/node_modules/@xterm/xterm/src/common/buffer/CellData.ts:37-42`; `BufferLine.translateToString` renders them as a space, `BufferLine.ts:551-581`), so the condition can snap left from an empty cell. **Fix:** use `getWidth() === 0` and, defensively, require `col > 0 && getCell(col - 1).getWidth() === 2`; add a blank-cell/end-of-line test.

- **[MINOR] N13 — Loopback/SSH copy is contradictory.** `design.md:241` says local open is usually unreachable and remote points to the desktop; `terminal-link.html:344` says “Only reachable on the remote host; desktop open uses your desktop Orca browser.” For a local terminal, `127.0.0.1` is the desktop; for an SSH session, the desktop may not reach the remote host either. **Fix:** use “usually not reachable from this phone; desktop open uses the desktop Orca browser”, and, if the session is SSH, say what the remote host is; add a copy assertion.

- **[MINOR] N14 — Floating-workspace behavior is still ambiguous and untested.** `design.md:85,93` says floating routes keep existing behavior with only local open (or remote hidden), while §7.1.2 only names folder/OTA; the current code directly opens local for floating (`mobile/src/session/use-mobile-session-file-actions.ts:92-96`). A5 only covers folder. **Fix:** decide whether the new sheet appears in a floating workspace with local/copy/cancel, or whether the existing direct-local behavior stays, and add a test.

- **[MINOR] N15 — Segmenter test isolation/locale and several weak vectors.** G20 (“delete `Intl.Segmenter`”) can pass without exercising the fallback if the tokenizer caches an instance; G21 must force both constructor and `segment` to throw and needs a reset/injection point. The design never specifies the Segmenter locale (`undefined` vs `zh`) or caching, so behavior can vary by device locale. G19/G23/G24/G25 have no exact cells/text, and B20 allows “select glyph **or** remain empty”, so either implementation passes. **Fix:** specify locale and cache, add a reset hook, and add exact vectors for combining/ZWJ/fullwidth punctuation/tab/blank lines. Make B20 choose one expected outcome.

- **[MINOR] N16 — Regression references point at the wrong files / undefined cases.** R6 cites `terminal-webview-tap-routing.test.ts` for “URL/path long-press copy”, but that file tests taps and its fake line is `text.slice(start, end)` — exactly the cell-as-string-index bug (`mobile/src/terminal/terminal-webview-tap-routing.test.ts:36-40`); there is no `selection-range`/`selection-overlay` test today (R7), and no `surface-tap.test.ts` (R8). A18 “floating fenced code URL” is not defined in the design. **Fix:** point R6/R7/R8 at the new width-aware selection tests, add the long-press URL/path case there, and define or drop A18.

- **[MINOR] N17 — Clipboard API reuse.** `design.md:86` specifies `expo-clipboard.setStringAsync`; the app already has `useClipboardWriter`/`platform/clipboard.ts` (`mobile/src/session/MobileSessionSheets.tsx:8,18`), and TL-T5 names it. **Fix:** use the existing abstraction in the design and sheet; do not add a second clipboard path.

## 待确认问题

1. **Legacy preference**: should a stored `orca-browser`/`phone-browser` be a one-time preselection that is then migrated to `ask`, or is a separate remembered key used? What exactly does “preselection/highlight” look like, and does the Remember switch start on when a legacy value exists?
2. **Remote open**: is the desktop tab focused or merely created? If focused, the current host moves the caller too; is a host-side “focus host only” change in scope? If not focused, use `activate: false` and say so.
3. **Remote capability**: what is the concrete “unknown” state — `connState`, host-status `statusPending`/`statusReadable`, or a new capability? What should an older host without the chosen non-activating path do?
4. **CJK merge >6**: which characters form the phrase for a 7+ character run, and does the fallback truncate a long CJK token?
5. **Fullwidth**: should `ＡＢＣ１２３` be one token in the fallback, and should `foo-bar`/`key=value`/`a@b.com`/`C++` remain one token as they do today under `WORD_RE`?
6. **mailto**: in scope? If yes, add the matcher and task; if no, remove A16’s local-open expectation.
7. **Floating workspace**: sheet with local/copy/cancel, or the existing direct-local behavior?
8. **Keyboard close**: restore the pre-open keyboard state or always leave it closed?
