# 父子会话沟通机制（主会话 ↔ 子代理协议）

> 版本：1（2026-11-14，用户指令确立）
> 适用：云端开发平台所有工作令的派发、跟催、回收；主会话=编排调度与快速检测，子代理=开发/测试/审计执行。

## 1. 角色与通道

| 角色         | 通道                                                | 职责                                                                                 |
| ------------ | --------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 主会话（父） | Agent 派发 / SendMessage 催办与追问 / Cron 周期盘点 | 拆解任务、派发、看护、核验收口、更新 PROGRESS 与台账                                 |
| 子代理（子） | 完成时自动回报（任务通知） / SendMessage 回复 main  | 执行单一任务；**被询问时必须用 SendMessage 回复 main**——直接文本输出对后台任务无感知 |

**核心规则：父会话向子代理提问时，消息里必须写明回复方式**（「请用 SendMessage 回复 main」或「结束任务让完成通知带回结果」），否则子代理的直接输出父会话无感知。

## 2. 派发规范

1. **一令一代理**：每个工作令（或细粒度任务）派一个全新代理；令内规格是唯一事实源（work-orders 文件）。
2. **两级审计梯（2026-11-16 用户指令合并原三权分立审计）**：实现代理 → 测试代理 → **审计梯**——①**令级审计**（原第三环，现降为**高风险令可选**：宿主安全边界/持久化/并发类才附加）；②**验收审计（每批必做，见 §3g）**。问题由主会话回派实现/测试代理；两级审计与实现/测试同样独立（不得参与该项实现/测试编写），只读+可复跑，不达标回派重测。原审计实践（U68 变异复现/LGAA 八项核查/W12b2/U46 批量/W9a-W9b）归入本体系。）
3. **20 分钟控制线（2026-11-14 用户修订，原 15 分钟目标）**：预估超时必须继续拆分；复杂令先派设计代理出方案，主会话确认再派实现。
4. **隔离**：主工作树有并发在途改动时，验证/旅程类代理用 `git worktree --detach <commit>` 隔离构建运行；实现代理用「逐文件 add + 提交前 `git diff --cached --stat` 核对=预期文件」。
5. **技术方案必备节：AC→测试用例映射表**（2026-11-15 复盘固化——验收代理按映射逐条执行的基础设施）。
6. **必带交付要求**：证据目录（`cloud-platform/evidence/<task>/`）、提交消息、测试输出（pass/fail 数）、超范围即停；**修复令另须留存 implementation.diff**（并发回退时的自恢复依据，2026-11-15 复盘固化）。
7. **pathspec 前核验（2026-11-16 复盘固化）**：主会话/代理对**非本会话编写**的文件做 pathspec 提交前，必看 `git diff --stat` 核对改动范围——外部写手会对工作树做格式化乃至截断（原型/设计文档/方法文档三例），不可假设「只有我刚改的一行」。
8. **诊断令词纪律（2026-11-16 固化）**：诊断/排查类令词只给**用户可观测现象与期望**，不得预设实现文件/类名——预设会牵引代理走向错误方向（U96 判例：任务词点名工作区组件后方向偏差，重派为「仅现象+自主功能发现」后恢复）。需要范围约束时用功能语言（如「两种工作区形态」）而非代码符号。
9. **设计交付形态（2026-11-16 复盘固化——U67/LDAP 两次实证）**：设计文档必含「终审项（T 编号）+开放问题（Q 编号）」清单与文末「主会话审定节」；独立评审清单含编号引用一致性检查；审定+评审双通过前不派实现令。
10. **诊断声明必须被设计复核（2026-11-16 13:05 复盘固化——U96 Q2 判例）**：设计代理须逐条复核诊断的关键代码声明（"已/未实现"类断言），不一致处显式标注；主会话审定包含对诊断结论的交叉核对。站���断言深度同源纪律：验收站点须对应用户可感知状态做深度断言（U91 restart 站点判例——站点绿不等于恢复内容正确）。
11. **构建产物隔离（2026-11-16 固化——U103 判例）**：验证/旅程类构建**禁止在主工作树原地重建 `out/`**——持久环境（~/orca-local-env 宿主）正伺服主仓 `out/`，构建替换会造成在线客户端「旧 index 引用已删 chunk」类故障（U103：刷新停留登录界面）；构建一律在快照目录（git archive/worktree）内进行；若确需主树构建，构建后必须立即 reseed 持久环境对齐（资产与宿主内存同版本）。
12. **台账现状复核（2026-11-16 14:05 固化——U101 判例）**：修复令执行前必须复核台账声称的缺陷现状；发现过时（已修/本就绿）时更正台账并在交付中声明，不得照旧修。测试令若因构建/环境受限无法执行，必须在交付中显式声明「执行待办+触发条件」，主会话跟进闭环。
13. **进程清理禁令（2026-11-16 复盘固化——U88 判例）**：代理清理进程**禁止宽域 `pkill`/`killall`**，尤其禁止按源码路径（如 `pkill -9 -f "apps/api/src/server.ts"`）、通用 node/bun 模式或端口号 pattern 扫杀——同机持久环境常以相同源码路径/端口启动，会被一并误杀。只允许：①kill **自己 spawn 的子进程 PID**（记录 PID 后逐个发信号）；②按**本次运行特有的唯一临时标识**（如本次专属临时目录、随机 marker）匹配。仓库 harness 即此范式（`cloud-platform/test/e2e/harness.ts` 以 `spawned` PID 注册表精确 SIGTERM/SIGKILL），手工清理须照办。
14. **用户面工件逐字断言（2026-11-16 15:05 复盘固化——U115 判例）**：命令/URL/文案类用户面工件的测试必须按**原文逐字**执行或断言，不得添加用户不具备的权限（如测试自带 adminToken 头掩盖照抄命令无凭据=假绿）。
15. **格式化洪水检测（同次固化）**：提交前若工作树 modified 文件数异常激增（>100 且非本代理域），视为外部写手格式化洪流——不整体提交、pathspec 前后复核目标文件仍是自己的编辑、必要时从 diff 重放。
16. **冒烟/重放三纪律（2026-11-16 17:05 复盘固化——v2.2 判例）**：①**基线探测先行**：持久环境复测前先探各项目标签/状态，选干净基线并记录污染源；②**终端内容断言不得依赖 DOM 文本**（canvas 渲染）——用宿主 `terminal.read`/xterm buffer API/截图，测完在报告标注测量方式；③**测量门与功能门分离报告**：自动化计数 false 若属测量噪声（外链、取文、基线污染）须逐条定性，不与功能失败混报。
17. **多实例 DOM 断言作用域（2026-11-16 18:05 复盘固化——U124 判例）**：同一状态被多实例渲染（split 双面板等）时，E2E 断言必须限定焦点/容器作用域，或**直接断言 store/宿主真源**；全局 `querySelector` 取首个命中=假红/假绿高危。
18. **仪器化构建收尾（同次固化）**：凡使用 `VITE_EXPOSE_STORE=true` 等仪器化构建跑验收后，交用户/做发布前必须：正式重建（去仪器化）→ `--platform-only` 刷新平台快照 → 核验 `window.__store` 标记为 0 且 served=源。
19. **契约影响面清单（2026-11-16 16:05 复盘固化——U130 判例）**：提交变更**授权谓词 / 契约白名单 / 网格 span / 字段集**时，须同批（或紧随一个提交）同步受影响测试与夹具，并在提交说明列出清单（例：U62-C10 收紧→5 夹具 7 例；U96 A-1 加性字段→白名单套件；U86 auditTrace→网格契约）。漏同步只会在下次全量回归暴露，代价是整批红与分诊时间。
20. **回归失败三桶分类先行（同次固化，验证有效）**：全量回归失败的**第一动作是分桶**——今日引入（按提交归属）／既有／环境（池/本机）——再决定派修；三桶分类把本次 15 红收敛为 3 项派修、6 环境项不误修。未分类不得直接派修或计入发布阻塞。
21. **持久化/重放路径首启验证（2026-11-16 17:05 复盘固化——U133 判例）**：启用此前从未启用的持久化或重放路径时，必须用**真实事件样本**（含可空字段的 null 值）做一次「写→重启→回放」验证，而非只用新造的全字段样本。判例：审计文件首次启用即因 `actor:null`（合法事件）被校验器判 corrupt，平台拒绝启动。
22. **验收基线计数机检（同次固化——三轮审计 REJECT 判例）**：`node cloud-platform/scripts/check-acceptance-counts.mjs` 必须 PASS——模块表逐行算术、合计列、§13 分类（closed/部分/待办）与结论行、business-flows 汇总全部从行状态推导；任何计数修改先跑脚本，审计/验收前必跑。
23. **会话/控制台变更后金路径复跑（同次固化——U138 判例）**：改动控制台脚本（`apps/web/app.js`）、会话恢复或平台持久化相关代码后，必须重跑金路径控制台线（journey 探针 13 门禁），不能沿用变更前绿结论。判例：P1 变更后复跑暴露宿主活动标签与 DOM/store 不一致（U138）。
24. **终端断言去折行（补充 §2-16）**：窄终端下 shell 提示符（RPROMPT）会产生**硬换行**，marker 匹配须在去折行流上统计完整出现次数，不得按行计数；不得因此把断言降为 ≥1。
25. **构建口味矩阵（2026-11-16 18:05 复盘固化——U36 复发判例）**：生产重建会折叠 e2e store oracle（`VITE_EXPOSE_STORE` 未置），`SKIP_BUILD` 跑 spec 时表现为「客户端未激活 checkout/ store 为空」的假产品回归。规则：跑 e2e/spec 前确认 out 构建口味（oracle 标志），需要时以 `VITE_EXPOSE_STORE=true` 重建；生产部署与 e2e 验证使用不同构建批次时，必须分别声明。
26. **一次采样 ≠ 稳定一致（同次固化——U138 判例）**：多方可变状态（活动标签/焦点/选择）的门禁不得只采样一次相等；必须断言「被操作实体在重载后存活」「连续 ≥2 次重开一致」「初采样 + 等待 N 秒后复采样」。U138 首次绿 run 即为采样相位巧合。
27. **钻取隔离（同次固化——U138 判例）**：journey/探针 drill 开始前清理或命名空间化目标 worktree 的持久选择（每设备 tab 选择、stale workspaceSession active），否则持久污染会让门禁相位随机，绿/红都不可信。
28. **同一缺陷二次派修前必须产出事件级写入时间线（2026-11-16 19:00 复盘固化——U138 五轮判例）**：状态同步类缺陷在没有「谁在何时写了什么、覆盖了谁」的时间线之前，不得连续派修；U138 前三轮均在假设驱动下修了不同分支（窗口权威→客户端回写→捕获点），第四轮时间线才锁定主因。时间线须含：各写入方 RPC/帧名、写前写后宿主 list 与持久值、客户端 store/DOM 值。
29. **多源状态先写权威矩阵（同次固化）**：涉及多层各自持有同一状态（宿主内存/宿主持久/每设备选择/客户端本地）时，先落一份权威矩阵（层×字段×优先级×收敛方向）再修；缺失矩阵是 5 轮返工的根因之一。
30. **聚焦探针先行迭代（同次固化）**：状态类缺陷用窄探针（如 `verify-u138-activation.mjs`）迭代验证，探针绿后再走「重建→reseed→全 journey」大循环；大循环每次 10+ 分钟，不应作为第一反馈环。
31. **语义分叉尽早升级（同次固化——U138 判例）**：同一缺陷第二次修复失败时，若存在「以谁为准」类产品语义分叉，立即带证据升级用户裁定，不继续在实现层试探；U138 五轮后才升级，代价过高。
32. **多周期重开纳入金路径标准站点（2026-11-16 20:00 复盘固化——U138 判例）**：单次 reload 不足以保证「活动标签稳定」；金路径须固定一个「打开→采样→关页→再开 ×3」站点并断言三方一致。U138 的宿主自翻转（无手势时 active 在两 tab 间交替）只有在多周期采样下暴露。
33. **RPC 帧可观测（同次固化，实验项）**：状态类诊断反复依赖反推「谁写了什么」。需要时在 web 客户端加一次性 debug 开关记录 `session.tabs.*` 的请求/回帧（默认关、不进生产），作为 §2-28 时间线的直接证据来源；下次同类诊断验证有效后转正。
34. **钻取隔离必须代码化（2026-11-16 21:00 复盘固化——U138 十轮判例）**：§2-27 只写成纪律却未在 drill 中执行，持久状态累积导致同一构建门禁时绿时红（journey-13/15/16 绿、-14/-17 红），十轮证据含糊。规则：依赖持久状态的门禁必须在脚本内提供隔离/清理步骤（新 worktree、清目标 worktree 的 per-device 选择与 stale active、或独立 device 命名空间），隔离缺失时门禁结果不得作为判绿/判红依据。
35. **判别字段的互斥性验证（同次固化——8b 判例）**：用某字段区分请求类别前，必须列出所有调用点并证明该字段取值互斥；U138 曾以 `intent:'user'` 区分用户点击与镜像 attach，但 transport 内部同样传 'user'，一轮部署被浪费。替代方案优先选**显式新增标记**（如 materializeOnly），而非复用语义重载字段。
36. **验收前台账对账（同次固化，实战有效）**：批次/验收前必须按「证据>git log>台账」对账非绿行；本轮对账 13 行发现 5 行状态滞后（U67b/U96/U98/U103/U125 实际已闭合）。对账结论以提交+证据路径支撑，无证据不判 CLOSED。
37. **共享文档提交纪律（2026-11-16 22:00 复盘固化——G 批判例）**：`current-state/**` 与台账属多代理共享文件，本轮至少 4 次出现「A 的提交带入 B 未提交的文档改动」。规则：①任一提交前运行 `check-acceptance-counts.mjs`，PASS 才提交；②代理提交共享文档必须用隔离索引/blob（`git add` 自己的行后 `git commit --only <file>` 或临时 index），提交后 `git show --stat` + `git status` 复核未卷入他人改动；③做不到隔离时改为主会话串行落盘；④每批结束由主会话跑一次机检 + `git diff HEAD~N` 抽查。
38. **重启与后台链收尾（2026-11-16 23:00 复盘固化——EADDRINUSE/泄漏判例）**：重启平台/宿主前必须确认**实际监听者**（`lsof -nP -iTCP:<port>`）而非只信 pidfile（本轮 pidfile 陈旧→新平台 EADDRINUSE）；`TaskStop` 后台链后必须枚举其子进程并按精确 PID 清理（本轮遗留 14 个测试 server）；spawn 前断言端口空闲。
39. **平台范围假设核验（同次固化——U80 判例）**：判断「某面是否需要适配/是否支持」时，先核验上游事实或用户澄清，不得仅凭旧方案文档断言（曾据旧文档称 Orca Web 不做移动端，用户澄清其上游自带移动端支持，范围因此收敛）。
40. **回归声明的范围口径（同次固化）**：全量回归结论必须写明执行范围与抽样口径；本机无法承载全量（12.4k 文件约 23 文件/分）时使用「与上次同口径可比批」并显式声明，不得以抽样批冒充全量绿灯。
41. **页面级测试独立文件（2026-11-17 00:00 复盘固化——M5 判例）**：新页面/模块的 e2e 从第一天就建独立套件文件（如 `u80-mobile-<page>.e2e.test.ts`），不要并入大壳套件直至触发 `max-lines`；拆分成本在实现期远低于后期。
42. **提交前工作目录自检（同次固化——两次 pathspec 失败）**：`git commit -- <path>` 前先 `git rev-parse --show-toplevel` 与 `pwd` 对齐，或一律使用绝对路径；本轮曾因 cwd 漂移到 `cloud-platform/` 导致 design 文档提交两次失败空转。
43. **原型一致性回归化（同次固化——M9 判例）**：探索性测试发现的「实现与原型不符」项，修复时必须同时补 e2e 断言（可测部分），防止回退；实现代理自写的 e2e 不得作为原型一致性的唯一证据，原型对照由探索阶段独立把关。
44. **审计代理停滞处置（2026-11-17 01:00 复盘固化——M8 审计判例）**：审计/只读代理若超过预算且转录文件 >5 分钟无更新，按卡死处理：TaskStop 后**缩小范围重派**（≤15 分钟、限定 2-3 套件、明示「禁止全量/长套件」）；重派版需带硬性时间盒收尾语（超时即带现有结论结束）。
45. **「工作树噪声」假设需 HEAD 快照证伪（同次固化——U149 判例）**：任何「失败来自他人未提交改动」的判断，必须先在 `git archive HEAD` 快照复跑；若 HEAD 同样失败，即为真实回归并登记台账（U149：HEAD 6/7 复现）。
46. **路由拦截断言纪律（同次固化——U149 判例）**：`page.route` 的 glob 必须覆盖查询串（`**/v1/projects*` 或 predicate），并在测试内断言拦截实际发生（计数>0）；产品把请求合并为带参 URL 时，旧 glob 会静默失效，错误态分支不再被执行。

小修改**不自动逐笔提交**——按**功能粒度**归并提交：同一功能/修复的完成态一起提交（中途修改在工作树保留，代理「完成即提交」含义=功能完成态，非每次文件保存）；跨功能完成态可分别提交但不得拆碎；文档/设计类按主题归并。事故 8 的 --no-verify+pathspec 纪律不变。

## 3f. 并发调度下限（2026-11-16 用户指令）

每轮跟进时**活跃并发 <3 即须立即安排新任务**（从队列/P2 挂账/路径清单演进/探索扩面中取最优先者派发），不让槽位空转；资源争用（真栈套件 CPU）是唯一允许 <3 的例外，且须在汇报中说明。并发上限维持 6（真栈套件并行时按 CPU 回撤）。

## 3g. 独立验收审计（2026-11-16 用户指令固化——U111 实践）

1. **触发**：每批用户问题/需求交付声明完成后，主会话先建**审计计划**（`work-orders/uNNN-acceptance-audit-plan.md`）：逐项「用户原话 → 实现提交哈希 → 证据目录 → 审计组」；未完成/仅原型项标注「暂不审」。
2. **独立性**：审计代理不得参与该项任何实现/测试编写；只读代码与证据，可自行复跑测试。
3. **三重核验**：代码（实现 vs 声明/静默降级/scope 边界）· 证据（存在性/时间戳自洽/断言真实性/负控/FAIL 诚实记录）· 复跑（自跑关键套件，不信转述；`it.fails→it` 转正须靠修产品而非放宽断言）。
4. **判定**：PASS / REJECT（列缺陷）/ RETEST（证据不足）——两者由主会话立即回派修复或重测，闭环前**不得向用户宣告该项完成**。
5. **报告**：`test-reports/uNNN-audit-*.md` + 主会话总评表（判定+缺陷计数）呈报用户。
6. **与原审计的关系（合并规则）**：原「审计代理」= 令级审计，已降为高风险令可选；验收审计为每批必做超集（增证据可信度核验+自跑复测+判定协议）；既有审计实践（U68/LGAA/W12b2/U46/W9a-W9b）语义归入本体系，不另设平行环节。

## 3i. 主会话决策权（2026-11-16 用户指令）

> 补充（2026-11-16 用户指令）：**开发环境的非危险操作（含中继/测试环境重启、证书替换、服务化配置）无需等待人工确认，主会话自行决策执行**；危险操作（生产系统、不可逆数据删除、外部可见发布）仍按关键项确认。中继当前未正式使用，可按需处置。
> **决策程序（2026-11-16 用户指令）**：遇到同类「需拍板」问题（范围/实现路线/界面取舍/流程分叉），在向用户请示前，**先启动 3 个独立子代理各自给出方案**（互不可见、独立推理），主会话按四标准择优或综合：①最合理（技术正确性/长期维护成本）②工作量可控（≤常识预算，可拆分）③贴近原始需求意图（解决真实问题，不做表面 UI 或只满足字面需求）④参考业界通行做法与 Orca 项目自身既有能力/惯例。决策结果与理由写入台账/文档；此程序不替代 §3i 的关键项确认。

1. **自主决策**：非关键矛盾（技术实现取舍、文案、内部接口、测试策略、优先级排序、P2/P3 处置）由主会话直接决策并执行，**不得挂起等人工**；决策记录写入台账/文档。
2. **仍须用户确认（关键项）**：产品语义/交互形态变更、破坏性操作策略、安全策略放宽、用户可见的重要取舍、发布到真实环境的时点（默认允许测试环境）。
3. **待确认提醒**：每轮（cron 汇报）必须列「待您确认」清单及建议——不得静默堆积；清单维护于台账顶部的「待用户确认」节。

## 3h. 业务链路与探索性测试强制门（2026-11-16 用户指令）

1. **验收前置（强制）**：任何验收批开始前必须具备——①按模块的**现状文档**（`current-state/mXX-*.md`，七要素模板）；②**业务链路图**（`current-state/business-flows.md`：入口→步骤→失败分支→模块/API→已有测试）。二者对应当前 HEAD，不得以设计稿/原型替代。
2. **探索性测试为必经环节**：以模块文档与链路图为输入逐链路探索、逐模块操作清单核对；路径清单入库复用；发现→台账→**转化为正式用例**。未执行探索不得宣告完成。
3. **用例基线**：用例必须可追溯来源（模块操作条目/链路步骤/AC）；失败分支与已知缺陷必须有对应用例；覆盖核对按模块文档逐条勾选，未覆盖显式裁定。
4. **闭环**：模块文档/链路图随每次修复更新基线提交；验收审计（§3g）按此基线核对证据完整性。

## 4. 任务多时的拆分

- 单轮并发 ≤4 个子代理（域不相交）；超出部分排队下一轮。
- 通道内串行（同一组件域同一时间只有一个代理）；通道间并行。
- 大任务拆到「单代理 15 分钟可完成」粒度；跨域耦合以已提交契约为界。

## 5. 回收与核验

1. 完成通知到达 → 核验四件：提交内容归属（`git show --stat` 逐文件对照工作令）、测试输出数字、证据目录齐备、与规格无偏差。
2. 审计/测试发现问题 → 回派实现代理修复 → 独立复验 → 三方齐备才关闭令、放行下一个。
3. 失败必须如实入 PROGRESS 与 defect-ledger（🔴→🟡→🟢 状态机），不为绿而改判定。
4. **人工复核反馈回路（2026-11-15 复盘固化）**：宣告「全部完成」后的人工复核反馈（含不通过）触发**证据链升级重验**——按路径清单重放+**每个功能步骤截图**（留盘不提交）；自动化断言「功能可用」≠人工认可「证据可核验」，验收材料双维度交付。
