# 父子会话沟通机制（主会话 ↔ 子代理协议）

> 版本：1（2026-11-14，用户指令确立）
> 适用：云端开发平台所有工作令的派发、跟催、回收；主会话=编排调度与快速检测，子代理=开发/测试/审计执行。

## 1. 角色与通道

| 角色         | 通道                                                | 职责                                                                                 |
| ------------ | --------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 主会话（父） | Agent 派发 / SendMessage 催办与追问 / Cron 周期盘点 | 拆解任务、派发、看护、核验收口、更新 PROGRESS 与台账                                 |
| 子代理（子） | 完成时自动回报（任务通知） / SendMessage 回复 main  | 执行单一任务；**被询问时必须用 SendMessage 回复 main**——直接文本输出对后台任务无感知 |

**核心规则：父会话向子代理提问时，消息里必须写明回复方式**（「请用 SendMessage 回复 main」或「结束任务让完成通知带回结果」），否则子代理的直接输出父会话无感知。

## 2. 派发规范

1. **一令一代理**：每个工作令（或细粒度任务）派一个全新代理；令内规格是唯一事实源（work-orders 文件）。
2. **三权分立**：实现代理 → 测试代理 → 审计代理接力；问题由主会话回派实现代理。
3. **20 分钟控制线（2026-11-14 用户修订，原 15 分钟目标）**：预估超时必须继续拆分；复杂令先派设计代理出方案，主会话确认再派实现。
4. **隔离**：主工作树有并发在途改动时，验证/旅程类代理用 `git worktree --detach <commit>` 隔离构建运行；实现代理用「逐文件 add + 提交前 `git diff --cached --stat` 核对=预期文件」。
5. **技术方案必备节：AC→测试用例映射表**（2026-11-15 复盘固化——验收代理按映射逐条执行的基础设施）。
6. **必带交付要求**：证据目录（`cloud-platform/evidence/<task>/`）、提交消息、测试输出（pass/fail 数）、超范围即停；**修复令另须留存 implementation.diff**（并发回退时的自恢复依据，2026-11-15 复盘固化）。
7. **pathspec 前核验（2026-11-16 复盘固化）**：主会话/代理对**非本会话编写**的文件做 pathspec 提交前，必看 `git diff --stat` 核对改动范围——外部写手会对工作树做格式化乃至截断（原型/设计文档/方法文档三例），不可假设「只有我刚改的一行」。
8. **诊断令词纪律（2026-11-16 固化）**：诊断/排查类令词只给**用户可观测现象与期望**，不得预设实现文件/类名——预设会牵引代理走向错误方向（U96 判例：任务词点名工作区组件后方向偏差，重派为「仅现象+自主功能发现」后恢复）。需要范围约束时用功能语言（如「两种工作区形态」）而非代码符号。
9. **设计交付形态（2026-11-16 复盘固化——U67/LDAP 两次实证）**：设计文档必含「终审项（T 编号）+开放问题（Q 编号）」清单与文末「主会话审定节」；独立评审清单含编号引用一致性检查；审定+评审双通过前不派实现令。
10. **进程清理禁令（2026-11-16 复盘固化——U88 判例）**：代理清理进程**禁止宽域 `pkill`/`killall`**，尤其禁止按源码路径（如 `pkill -9 -f "apps/api/src/server.ts"`）、通用 node/bun 模式或端口号 pattern 扫杀——同机持久环境常以相同源码路径/端口启动，会被一并误杀。只允许：①kill **自己 spawn 的子进程 PID**（记录 PID 后逐个发信号）；②按**本次运行特有的唯一临时标识**（如本次专属临时目录、随机 marker）匹配。仓库 harness 即此范式（`cloud-platform/test/e2e/harness.ts` 以 `spawned` PID 注册表精确 SIGTERM/SIGKILL），手工清理须照办。

## 2b. 并行模式（用户 2026-11-14 指令：不要串行开发，单独完整链路验收，发现即修不堵塞）

1. **开发令派发不再以「前一令测试/审计通过」为前置**：实现落地即放行下一开发令（同通道后续令与跨通道均可）；文件域不相交仍是硬约束（防工作树碰撞与提交卷入）。
2. **三权分立保持但并行化**：独立测试与审计与后续开发**同时**跑，不再作为闸门串联；发现问题回派修复，修复本身也是开发令。
3. **完整链路验收=批量+异步**（用户 2026-11-14 追加指令）：不逐令逐波验收——积批（多个开发令落地或定时）后由专职验收代理对**当时 HEAD** 跑全链（双线黄金旅程 chain-smoke + 管理员链），占用一个普通槽位与开发并行；结论异步回流，**红项批量进修复队列**，绝不等待验收结果才派下一批开发。
4. **双绿仍是终局门禁**：向用户汇报「全部完成，等待人工验收」之前，双线黄金旅程必须全绿。
5. 并发上限 4 不变（真栈套件 CPU 争用会互相拖慢并致时序测试抖动）；空槽即时回填，不让槽位等待。

## 3. 看护（看消息时间，不看钟表）

1. **正常推进（未空闲/未堵塞）→ 不打扰**：以「最后消息/证据目录最新文件时间」判断；刚回报过状态或证据在增长的代理一律不催。
2. **超过 1 小时无最后消息 → SendMessage 了解**，且**必须写明回复方式**（见 §1）。
3. **确认卡死（无证据推进 + 询问无响应）→ TaskStop**，按剩余范围重派新代理（附前序遗留 diff 审阅指引，能续用则续用）。
4. **反例存档**：对 W9a 的过早催办（其正按自己节奏收尾且已主动回报）——催办前先看它最近是否已主动回报。
5. **环境体检（2026-11-16 复盘固化）**：看护轮含持久环境面检查——四进程存活+关键端点 HTTP 探针；异常即用幂等 reseed 一键恢复（U77 后脚本自愈闭环），平台静默掉线判例（05:05 复盘）不入阻塞、不惊扰用户。
6. **状态读数优先级（2026-11-16 复盘固化）**：证据文件 > git log > 台账行 > 会话记忆/摘要——台账行与文档 header 滞后是常态（U66 行滞后 APPROVED、W12 header 滞后已落地两例），任何派发/回收动作前按证据文件与 git log 核验当前态。

## 3a. 探索证据留存纪律（2026-11-15 用户指令）

探索性测试的**证据/截图保留在磁盘但不随 git 提交**：findings JSON、截图、运行日志统一落 `cloud-platform/evidence/<轮次>/`（该目录在 .gitignore 中）；**可复用的是路径清单与脚本**（入库，见 §3b），不可复用的是一次性证据（留盘不入库）。两类产物严格分离。

## 3b. 探索路径复用（2026-11-15 用户指令）

探索性测试的**路径本身是资产**：每轮探索的页面/控件/API/链路操作序列必须整理为结构化路径清单（条目=「入口→步骤→检查点」，可附可执行脚本）**入库** `cloud-platform/scripts/exploratory-<轮次>/`，与 findings（evidence，gitignored）分离。后续回归/修正探索直接按路径清单重放，发现的修复以新用例追加进清单——路径清单持续演进，不重写。
