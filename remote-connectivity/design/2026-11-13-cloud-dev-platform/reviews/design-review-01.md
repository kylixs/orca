# 设计评审 01

> 日期：2026-11-13
> 范围：requirements.md、design.md、diagrams.html、tasks.md（v1.1）
> 评审人：独立评审子代理（只读）
> 结论：**REJECTED**

---

## 结论摘要

架构主线（平台只做注册与授权、客户端自行建链、中继纯转发）在需求、设计、图表三处一致，无旧方案残留。但存在 **2 个阻断问题** 与 **13 个主要问题**，集中在：凭证生命周期与选路互斥、托管准入两套互斥契约、撤销语义缺前置条件、下载管控承诺过度、审计哈希链并发定序缺失。

---

## Findings

### BLOCKER

| 编号 | 问题                                                                                               | 影响                                                                                   | 修改                                                                                                                    |
| ---- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| B1   | 凭证 `jti` 一次性（TTL 120s）与「多地址探测 → 回落中继 → 重连」互斥                                | 凭证在第一次探测即被消耗，后续端点、回落、重连全部 4401；FR-5.2/5.4、AC-19/20 无法实现 | 探测改为**不带凭证的 TCP 预检**；凭证只用于最终一次升级；重连必须重新签发                                               |
| B2   | 托管准入存在两套互斥契约（升级头统一 vs `e2ee_hello_managed`），且 `/connect` 未返回主机 E2EE 公钥 | 客户端无法派生共享密钥，托管连接根本建立不了；两套契约只能选一                         | 统一为「升级头凭证 + 原 E2EE 握手不变」；`/connect` 增加 `host.e2eePublicKeyB64`；凭证携带 `devicePubKey`/`deviceToken` |

### MAJOR

| 编号 | 问题                                                                                | 修改                                                                        |
| ---- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| M1   | 中继「不依赖平台」与「下线立即摘路由」矛盾                                          | 增加平台→中继的单向路由表同步（mTLS、版本 + TTL），并说明路由陈旧不等于越权 |
| M2   | 60 秒撤销缺少「心跳正常」前置条件；Access Token 宣称不单独吊销与强制下线冲突        | AC 补前置条件；会话纪元校验实现即时吊销                                     |
| M3   | 「平台与中继不可解密」是绝对承诺，但平台是密钥分发者                                | 声明信任根与 TOFU；删除绝对表述                                             |
| M4   | 文件权限粒度无法在现有 RPC 权限层执行（现状只有 `workspace`）                       | 新增方法→权限映射表；未登记方法默认拒绝                                     |
| M5   | 凭证只绑定 `projectRoot`，用户可读写他人 worktree                                   | 凭证绑定 `workspaceRoot`（写）+ `projectRoot`（读）                         |
| M6   | 下载「服务端强制」边界不诚实（剪贴板在客户端、`readChunk` 可重建文件）              | 重写能力矩阵，区分「可强制/不可强制」；G4 改为受管客户端口径                |
| M7   | 残余风险漏 `git push`、包发布、AI Agent 联网、浏览器上传                            | 补齐风险行与缓解                                                            |
| M8   | 审计哈希链在 3 副本并发写会分叉                                                     | 单写入序列（leader 选举 + seq），并发测试入 AC                              |
| M9   | 外网用户访问平台 API 的路径矛盾                                                     | 明确 WAF 只放行认证与项目/connect，管控面仅 VPN                             |
| M10  | 接口与数据模型缺归档、项目级策略、设备吊销、角色覆盖、JWKS 刷新、分页、主机长期凭证 | 逐项补齐                                                                    |
| M11  | 错误码冲突（4409 双重含义）且不完整                                                 | 分层错误码表；帧过大改用 1009                                               |
| M12  | macOS / Windows / CentOS7 开发机缺设计与任务                                        | 新增平台支持章节与任务                                                      |
| M13  | 任务依赖错误、里程碑不可达、工作量偏低                                              | 重排里程碑与依赖，重估                                                      |

### MINOR

术语「票据」混用；5.2 重复行；审计容量数字不自洽；版本号与失效链接；图表路径偏差；一期/二期边界冲突；审计热冷存储描述冲突；部署缺 KMS/LB/DNS 故障模式；缺 NTP 假设与凭证通道 TLS 要求。
