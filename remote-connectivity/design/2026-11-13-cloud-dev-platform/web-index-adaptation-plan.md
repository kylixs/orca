# orca web（web-index.html）改造方案

> 版本：2（2026-11-14，扩充背景/目标/要点）
> 状态：设计定稿，实施于工作令 W6/W7；细节以 work-orders-2026-11-14.md 为准
> 关联：FR-3.10 / FR-3.11 / FR-3.12 / FR-4.12 修订 · design.md §4.3.2 · deployment-real-link.md §4b

## 1. 背景

### 1.1 需求来源
- 开发者双使用形态（FR-3.12，用户确认）：桌面客户端之外，需要**从云端平台一键打开浏览器版完整 Orca** 并直接进入项目工作区。
- 跨网段现实：内网开发机对外网/跨网段浏览器不可直达，必须经中继；而桌面客户端经中继零配置（显式 SNI），浏览器做不到。

### 1.2 浏览器与桌面客户端的本质差异（方案根因）
| 维度 | 桌面客户端（Node TLS） | 浏览器 |
|---|---|---|
| 拨号地址 vs TLS 身份名 | 可解耦：直拨 IP:端口，`servername` 显式写任意 SNI | 绑死：SNI=URL 域名=DNS 解析目标 |
| 证书信任 | TOFU 指纹固定，自签即可 | 必须过浏览器信任链 |
| 端点来源 | 平台下发端点列表逐个探测 | 只能靠 URL |

### 1.3 orca web 现状
已有：完整 App 图谱（与桌面同一界面，含终端 WebGL 管线）、云平台登录表单（WebConnectCloudForm）、浏览器会话持久化与恢复（M62，localStorage）、宿主静态伺服（web-index.html）。
缺失：平台侧入口与免登录进入（每次要手输平台地址+账号）、跨网段经中继的传输路径（SNI 无法显式指定）、多宿主路径路由下的资源与 WSS 前缀适配。

## 2. 目标

1. **一键进入**：平台项目行点「Orca Web」→ 新标签直接落在该项目工作区，全程免二次登录（一次性交接码，令牌不经 URL/日志）。
2. **单域名经中继**：外网/跨网段浏览器仅凭一个中继固定域名即可使用，无需通配 DNS、无需逐宿主证书。
3. **功能面对等**：终端（实时输入/输出）、文件树浏览与只读预览、Agent 会话——与桌面一致（FR-3.9/3.12）。
4. **安全边界不变**：平台不进数据路径；E2EE 应用层端到端；授权/审计语义与桌面完全一致。
5. **非目标（明确排除）**：不做平台代理转发（违反 D1）；不做下载审批流（二期）；不做移动端布局。

## 3. 总体方案（三段式）

```
┌─ ① 平台：签发交接码 ──────────────────────────────────────────┐
│ POST /v1/projects/{id}/web-handoff（open 权限，审计 web_handoff）│
│ → {url: <web入口>#handoff=<code>&project=<id>}（code 60s 单次） │
└──────────────────────────────────────────────────────────────┘
┌─ ② orca web：消费交接码 ─────────────────────────────────────┐
│ 启动读 hash → POST /v1/web/handoff 换正式会话（复用设备会话签发）│
│ → 自动打开项目 → hash 用后即清 → 失败回落登录表单               │
└──────────────────────────────────────────────────────────────┘
┌─ ③ 中继：浏览器模式承载传输 ─────────────────────────────────┐
│ 直连可达：wss://<宿主>:<port>                                  │
│ 跨网段：wss://<中继域名>/h/<routeKey>/...（TLS 终结+路径转发）  │
│ E2EE 应用层不变——中继只见传输层头部，不见终端/文件/Agent 载荷   │
└──────────────────────────────────────────────────────────────┘
```

## 4. 要点详述

### 4.1 handoff 自动进入（W7）
- **动机**：令牌不能进 URL（浏览器历史/代理日志），又要求免二次登录——用一次性短时代码作中转。
- **设计**：平台内存 map（code→{userId, projectId, exp}，消费即删）；换发复用既有设备会话签发路径（与桌面同权同审计）；hash 用后即清（与 pairing 串同法，防 Referer/历史泄露）。
- **备选与取舍**：短期 ticket 直接拼 query（被否——URL 留痕）；持久授权（被否——违背一次性语义）。

### 4.2 经中继传输：中继双模式（W6，传输侧）
- **动机**：浏览器 SNI 绑死域名。
- **设计**：中继新增浏览器监听（TLS 终结 + 路径 `/h/<routeKey>/` 路由），SNI 透传模式与既有端口完全不动（线上兼容）。
- **备选对比**（用户已裁决）：子域通配（需泛 DNS + 逐宿主证书，废弃为主案备选）；Cookie 亲和（免改 web 包但一浏览器限一宿主，记为降级选项）；平台代理（违反 D1，排除）。
- **取舍要点**：中继可见传输层头部/路径——在审计与部署文档如实声明；E2EE 载荷不可读（AC-24 判据保持）。

### 4.3 路径前缀下的 web 适配（W6，web 侧两处）
- **资源相对 base**：vite `base:'./'`，`/h/<routeKey>/assets/...` 正确解析；直连无前缀天然兼容。风险：verify-web-build 校验需在两种 base 下通过。
- **WSS 前缀推导**：运行时从 `location.pathname` 提取 `/h/<routeKey>` 拼在固定 rpc 路径前；中继对 HTTP/WSS 统一剥前缀。备选 Cookie 亲和被否（多标签互踩）。

### 4.4 会话恢复优先级与多项目（W7）
- 启动决策：显式 handoff > localStorage 已存会话（M62）> 登录表单；handoff 成功覆盖存储。
- 多项目：每项目独立会话连接（对齐桌面 M53 语义）；同浏览器第二标签互不影响。

### 4.5 错误回落（W7）
- code 410（过期/重放）/403（无权限）/网络错误 → 内联提示 + 清 hash 回登录表单（WebConnectCloudForm 预填平台地址，衔接 W10 的地址记忆）。

## 5. 安全语义汇总
- 交接码：一次性、≤60s、绑定用户+项目、消费即删、审计 `web_handoff` 记 code 指纹（不含明文）。
- 令牌：仅经换发端点下发到页面存储（localStorage，沿用 M62 保护），不出现在 URL/Referer/代理日志。
- 中继：浏览器模式可见传输层元数据；E2EE 载荷端到端不可读；元数据记录 routeKey。

## 6. 测试策略
- 平台侧：签发→换发→重放 410→过期 410→无权限 403；审计断言。
- web 侧：hash 清除、自动打开、回落表单、WSS 前缀构造、相对 base 资源零 404、直连回归、多标签并行。
- 端到端：链路 B 冒烟（B1–B8）随 **W9 双线黄金旅程**收口（时间线 JSON + 截图）；三进程真实环境（平台+浏览器模式中继+宿主）。

## 7. 里程碑映射与风险
| 令 | 交付 |
|---|---|
| W4 | 无 bundle 时静态 503 兜底（前置健壮性） |
| W6 | 中继浏览器模式 + browserHost/browserEntryUrl + web 相对 base + WSS 前缀 |
| W7 | handoff 签发/换发 + web 自动进入 + 平台「Orca Web」入口激活 |
| W9 | A/B 双线黄金旅程收口 |

风险：① 升级请求头透传差异（W6 e2e 覆盖）；② 相对 base 对既有构建校验的影响（双 base 验证）；③ 中继 TLS 终结的合规评审（安全语义已如实声明，待安全评审确认）。
