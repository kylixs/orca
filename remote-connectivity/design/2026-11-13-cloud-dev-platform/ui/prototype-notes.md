## 0. 授权模型定型（最终裁定，2026-11-15，用户确认）

**资源类权限 = 资源 + 角色授权；位置即权限。**

1. 项目 / 主机的权限页签 = **纯角色授权**：每个主体授予 **查看 / 控制 / 管理** 三角色之一，不存在「自定义逐位开关」。U65 的级别选择器 / provision / maintain / view 逐位形态废除。
2. **位置即权限**：主体出现在哪张卡片，即拥有哪个角色的权限；主体行 / 条目只显示 **名字 + 类型徽标（组 / 用户）**，不写任何权限词尾注（全权 / 只读 / 查看 / 控制管理 / 权限位列表等一律不写）。权限含义的完整说明只在卡片头部说明区出现一次。
3. **层级规则（替代并集合成）**：查看 < 控制 < 管理 单向层级，高级隐含低级；同一主体**只出现在其被授权的最高级别卡片**，不重复出现。
4. **U65 语义矩阵的混合位并集合成规则作废**：原「查看 + 管理 ⇒ 隐含全权」「多卡片位取并集」等合成规则不再使用；改卡 = 调整角色（升级即时生效，降级断开该主体当前云会话，约 60 秒内生效）。
5. 卡片 ↔ 存储位映射表不变（见 §1），仅作为存储层实现细节，不再作为 UI 语义暴露。
6. **全局类权限 = 用户管理页的平台角色**（普通 / 审计员 / 管理员），与资源授权分两层：角色决定管控面 / 审计面可见性，资源授权决定「谁能用哪些项目 / 主机」。角色 ≠ 资源授权，管理员也不隐含项目内全权（打开项目仍需显式授权）。
7. **「成员与权限」页面整体删除**（原只读总览方案也作废）：授权唯一入口 = 项目详情弹框「权限」页签 + 主机详情抽屉「权限」页签。旧路由 `#/members` 回落到工作台。

## 1. 三卡片 ↔ 权限位映射（存储层，语义详见设计文档 §2）

| 卡片（角色） | 主机侧存储位 | 项目侧存储位 |
| --- | --- | --- |
| 查看 | `view` | `open + file:read` |
| 控制 | `view + provision` | `open + file:read + terminal + agent + file:write`（download 仍受项目 / 全局下载策略独立约束） |
| 管理 | `provision + maintain` | 项目级无「管理」位：主机授权推导只读视图（控制 / 管理主体），在主机详情弹框维护；归档 / 登记归创建者或平台管理员 |

- 同一主体加入多张卡时权限位取并集、行尾徽标显示合成级别——**该展示规则已作废**（见 §0），映射本身保留。
- 卡头位徽标已按 U65 C13/C14 与用户「权限注释多余」反馈移除：卡片头部只留角色名 + 主体计数，位信息仅存本节映射表。
- 授权语义基线：U65 审定（全权不含 maintain、download 不推导、只读 = open+file:read 上限、授权收缩撤凭证 ≤60 秒）。
- 三张卡片是主机授权位（view / provision / maintain）的分组视图：同一主体加入多张卡时权限位取并集，行尾徽标显示合成级别。项目级授权不扩大到主机级。（原主机权限页签头部说明，已迁移）
- 授权的新增 / 移除 / 覆盖统一在项目详情弹框「权限」tab 的三卡片中操作；本页矩阵保留为跨项目只读总览，行内「编辑」跳转对应弹框。（原成员页收敛说明，已被「页面整体删除」取代）
- 变更即时保存（PUT 整行替换）；已存在于其它卡片时先弹覆盖确认。降级保存将断开该主体当前全部云会话，≤60 秒生效（FR-1.7）。（原卡片尾注）
- 主机只读是项目内操作的上限：主机只读用户即使在本项目被授予终端 / 编辑，也只能打开查看，编辑、终端与 Agent 入口仍会置灰。（原成员页警示，U65 只读视角语义）

## 2. U67 · 授权方案重构（设计稿 · 2026-11-15）

- 主机详情抽屉 tab 化（信息 | 权限）：权限 tab 改为「查看 / 控制 / 管理」三卡片，每卡片=权限说明 + 主体 chips + 添加输入（目录 datalist）+ 移除；卡片↔权限位映射：查看=view、控制=view+provision、管理=provision+maintain（U65 语义矩阵，不新增权限语义）。原 U65 级别选择器 / 逐位开关被三卡片取代（收敛形态）。
- 新增项目详情弹框（工作台 / 我的项目行内「详情」，admin）：信息 | 权限双 tab；权限 tab 三卡片同构，项目级映射：查看=open+file:read、控制=terminal/agent/file:write/browser/download（下载仍受策略）、管理=主机授权推导只读视图（FR-9.11③ 不扩大）。
- 交互：添加 / 移除即时保存（PUT 整行替换），覆盖与整行删除弹确认（含 before→after 级别与 ≤60 秒断会话提示，FR-1.7）。
- 新增「用户管理」页（admin）：账号列表 + 平台角色下拉（普通 / 审计 / 管理员）；角色=平台级身份（管控面 / 审计面），与三卡片的资源授权分两层；角色变更写入 role_update 审计，按用户覆盖优先于 LDAP 同步。
- 成员与权限页收敛为跨项目只读总览：行内「移除」改「编辑」（跳项目详情弹框权限 tab），「添加成员」改「编辑授权 · 详情弹框」。——**后续修订：该页面最终整体删除（§0 第 7 条）**。

## 4. U65 · 主机授权语义深化（2026-11-15）

- 主机详情抽屉新增「权限分配」：全权 / 只读两档快捷级别 + 逐位自定义（provision / maintain / view）。——**后续修订：逐位形态废除，改纯角色三卡片（§0）**。
- 新增「只读用户 lisi」演示视角：项目可打开查看，工作区内编辑 / 终端 / Agent 入口置灰，无「新建项目」入口。
- 成员与权限页补充项目级授权说明：仅影响当前项目，不扩大到主机级；未授权项目不可见、不能创建。
- 下载入口按下载权限置灰：一期在 Web / 客户端前端拦截，服务端与宿主硬拦为二期。

## 5. 下载分期（拦截 / 审批流）

- 下载拦截分期落地：一期在 Orca Web / 客户端前端将下载入口置灰并记录拦截审计；服务端与宿主侧硬拦在二期上线。
- 项目下载策略一期仅支持「禁止」与「允许」；「审批后允许」选项与审批流在二期开放。
- 下载权限需在「下载策略」中单独开启，并需审批流支持（二期）；成员权限不会自动包含下载。
- fail-closed（U66-review-r2 N-2）：下载入口仅在宿主显式返回 `downloadAllowed=true` 时显示；字段缺失按禁止处理（`workspace.info` 为 U65 依赖）。
- 审批流暂未开放：下载拦截弹框中「拦截阶段 / 服务端宿主硬拦 / 审批流」分期行已从用户界面移除，迁移至此。

### 8.1 常用查询条件（U81）

- 条件集定稿三项：**用户名关键字**（显示名或账号子串，即输即筛）/ **角色**（全部/普通/审计/管理员）/ **状态**（全部/活跃/已停用）+ 「查询」（提交兜底，与即输即筛并存）与「重置」按钮 + 空态行（`没有符合筛选条件的账号`）。

- 未纳入本期的条件（如部门 / LDAP 组 / 创建时间段）：见设计文档 §7.1 增量修订 Q 清单。
