### T1 · DOM 策略推荐：响应式同一套 DOM（终审项）

推荐响应式同一套 DOM + 断点 CSS + 少量组件级分叉，理由：

1. **面少且同构**：管理台仅 8 路由 + 覆盖层，每页结构都是「页头 + 筛选 + 列表 + 弹框」，表格↔卡片、弹框↔sheet 是机械变换，一套 DOM 可覆盖，不值得双份维护。
2. **守卫逻辑只有一份**：admin-only 隐藏、审计 admin+auditor 可见性、权限三卡片语义、降级断会话警示等守卫与文案若复制到独立移动面，必然漂移（两处改一处漏一处）。
3. **无性能障碍**：管理台无重型画布（重型的是工作区终端 WebGL，而工作区面本就排除在 T1 之外）；断点 CSS 的成本可忽略。
4. **规模匹配**：独立移动面 = 独立回归 + 双倍 UI 维护，当前团队规模与迭代频率不匹配。

边界（不适用 T1 的面）：开发工作区（宿主 cloud-admin.html / 独立 Orca Web）保持桌面优先，移动端只保「入口可达 + 状态可视 + 桌面引导」，见 §4。

## 3. 关键页形态要点

1. **登录**：单列、44px 输入 / 48px 提交；错误提示、密码可见切换、使用规范链接与桌面语义一致。
2. **工作台**：欢迎语 + 只读视角通知（演示脚手架触发）+ 统计 2×2 + 最近项目（2 卡）+ 全部项目（卡列表，离线项目主操作置灰显示「主机离线」）。
3. **项目列表**：搜索框 + 状态 / 授权方式 chips；卡片字段 = 可见范围 + 最近使用；操作 = 详情（admin）+ 打开工作区（离线置灰）。
4. **项目详情（含权限 tab）**：全屏 sheet；信息 tab 字段纵列；权限 tab 三卡片（查看 / 控制 / 管理）+「位置即权限」与 ≤60 秒断会话说明；管理卡保持推导只读视图说明（桌面语义零改动）。主体移除的覆盖确认仍为居中小卡。
5. **用户管理（U81+U82）**：常用查询条件 = 用户名搜索 + 角色 / 状态 chips（建议集已按 U81 采纳）；列表纯只读（无行内下拉），角色徽标 + 「详情」入口（U82）。
6. **用户详情（U82）**：字段纵列（LDAP 组 / 角色来源 / 状态）+ 角色内联 select + 保存；变更即弹警示条——降级 =「断开当前全部云会话 ≤60 秒」，升级 =「即时生效不断会话」；语义与桌面 role_update 落链一致。
7. **审计查询（重表格最难点解法）**：
   - 10 字段筛选 → 页头「筛选」按钮（激活数徽标）→ 全屏筛选 sheet，字段分组（关键字 / 时间 / 操作 / 范围 / 结果）+ 吸底查询 / 清除；高频条件（全部操作 / 下载族 / 复制族 / 拒绝）另以 chips 前置。
   - 7 列事件表 → 事件卡：L1 操作名 + 事件类型 mono 徽标 + 结果徽标 + 时间；L2 用户 · 项目 · 主机；L3 文件 / 大小（mono 截断条）；「详情」行内展开（可信度徽标 / 会话 / 摘录状态）。
   - 分页 → 「加载更多」；覆盖范围与限制折叠块保留（默认折叠，窄屏省纵向空间）。
8. **交互守卫**：admin-only 路由对无权角色不渲染入口（非置灰）；审计 tab 对只读角色隐藏；详情 / 工作区入口对只读视角隐藏或置灰；守卫回落（forbidden）形态零改动。原型以演示脚手架切换验证（§5）。

## 4. 边界裁定：工作区面如实标注（范围已按用户澄清修正）

- 平台无业务流量、桌面客户端承载工作区的架构约束不变；U80 只适配**管理台（apps/web）**。
- **Orca Web 工作区上游自带移动端支持**（用户 2026-11-16 确认）：移动端用户经「打开工作区」/ 交接码直达即可使用终端、文件树与 Agent，无需本平台适配。
- 宿主 cloud-admin.html 内嵌覆盖层 = **桌面形态**：移动端不加载，管理台入口提示「移动端请打开 Orca Web 工作区」。
- 依据：用户澄清（2026-11-16）；旧版「Orca Web 不做移动端布局」表述作废。

## 5. 演示脚手架说明（非产品功能）

- 「更多」sheet 内的视角切换（管理员 / 审计员 / 只读 lisi）为原型演示脚手架，用于评审时验证守卫形态（admin-only 隐藏、审计可见性、详情入口置灰）；真实产品无此控件（与桌面原型同约定，见桌面 prototype-notes.md §7）。
- 登录页任意非空提交即进入工作台；审计筛选「查询」写入的激活数徽标为演示值。
- 「打开工作区」在原型中仅 toast 说明行为，不实际发起 handoff。

## 主会话审定（2026-11-16，随 U80 设计交付）

- **T1 定稿：响应式同一套 DOM**（采纳推荐——面少且同构/守卫逻辑单份/维护规模匹配）；**工作区面豁免**（桌面优先不重排，架构边界不动）。
- **T2 定稿：底部 tab 不硬编码三项**——按当前角色可达的导航面前三个派生；不足三项按实有数量渲染（规则化，auditor/developer 视角自动成立，Q1 一并解决）。
- **T3 定稿：审计事件详情=行内展开**（避免移动端深层级；全屏 sheet 保留给筛选入口）。
- Q1-Q8：不阻塞——Q1 随 T2 规则消解；Q4（卡片批量/排序）与 Q7（窄屏最小列集）留实现评审；Q2/Q3/Q5/Q6/Q8 留用户复核或部署期核实。
- 偏差追记：交付在盘 ~50 分钟未提交（外部排队/验证收尾超时），经看护询问后完成提交——无内容损失。
