## 1. 背景与目标

公司研发环境分散在办公网与内网机房，开发者需要在自己的电脑上通过 AI 编程工具（Claude Code 等）连接远端开发机完成开发。现状问题是：每台开发机各自配对、各自授权、无人审计，代码与凭证散落在个人设备上；跨网段访问依赖临时隧道，稳定性与合规性都无法保证。

本项目建设一个公司内部的**云端开发平台**：以 Orca 为客户端与运行时基础，在其上增加企业身份、项目目录、主机注册、地址发现与审计能力。平台不承载业务流量。

### 1.1 建设目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 员工用公司域账号一处登录，进入工作台看到自己有权限的项目 | 登录到项目列表 ≤ 2 次点击 |
| G2 | 打开项目即获得与本地 Orca 一致的开发体验（终端、Claude、编辑器、文件浏览） | 功能清单对齐，交互无额外学习成本 |
| G3 | 开发机统一注册，客户端直连优先、中继兜底，办公网与外网用户都能稳定连接 | 连接成功率 ≥ 99%，直连 P95 ≤ 2s，中继 P95 ≤ 3s |
| G4 | 受管客户端内禁止专用导出入口；主机拒绝专用下载 RPC；所有导出尝试可审计 | 受管客户端导出入口拦截 100%，主机拒绝率 100%，审计可追溯（内容读取不受阻断，见 C1） |
| G5 | 平台可运维：主机、项目、权限、审计集中管理 | 管理员无需登录开发机即可完成日常运维 |

### 1.2 设计原则

1. **复用优先**：客户端与运行时基于 Orca 上游，不另起炉灶；企业能力以补丁层形式叠加。
2. **平台只做注册与授权**：平台是注册中心 + 认证授权中心，签发地址与凭证；业务流量由客户端与开发机直接建立，平台不参与、不转接、不解密。
3. **端到端加密不被削弱**：客户端与开发机之间保持 Orca E2EE；中继只做 TCP 转发。
4. **默认拒绝**：未授权项目不可见，未授权操作不可用，下载默认禁止。
5. **可回退**：平台故障不影响已有会话；中继故障不影响直连；新会话降级而非整体不可用。

## 2. 角色与术语

### 2.1 角色

| 角色 | 说明 | 主要诉求 |
|---|---|---|
| 开发者（Developer） | 使用平台进行日常开发 | 快速登录、快速打开项目、稳定的终端与 AI 会话 |
| 项目负责人（Project Owner） | 对某个项目的成员与策略负责 | 管理项目成员、调整项目级权限 |
| 平台管理员（Platform Admin） | 负责主机、项目登记、全局策略 | 注册/下线主机、创建项目、配置下载策略 |
| 审计员（Auditor） | 安全与合规角色，只读 | 查询审计日志、导出证据（需审批） |
| 开发机（Dev Host） | 运行 Orca Runtime 的受管主机，非人类角色 | 注册、心跳、执行工作区与终端 |

角色由 LDAP/AD 安全组映射，不手工维护用户名单。

### 2.2 术语

| 术语 | 定义 |
|---|---|
| 开发平台 / 平台 | 本文所述系统整体，包含平台后端（注册 + 认证授权）、Web 管理台、中继、开发机 Agent、桌面客户端 |
| Orca Runtime | 跑在开发机上的无头 Orca（`orca serve` / orcad），负责 PTY、Agent、文件、Git |
| 项目（Project） | 一台已注册开发机上的一个受管代码目录（git 仓库或 worktree），是权限与审计的最小单位 |
| 工作区（Workspace） | 项目下按分支/任务创建的具体工作目录，对应 Orca 的 worktree |
| 中继（Relay） | 部署在 DMZ 的纯 TCP 转发组件，仅在客户端无法直连开发机时提供通路 |
| 直连（Direct） | 客户端直接到达开发机 `6768` 端口的路径（办公网/VPN 内） |
| 连接凭证（Connection Credential） | 平台签发的短时效凭证，声明某用户在某项目上可连接某主机；由开发机验签 |
| 托管项目（Managed Project） | 由平台登记并强制执行策略的项目；未登记目录不可通过平台打开 |

### 2.3 平台形态

平台本身是一个 **Web 前后端分离系统**：

```
┌───────────────────────────┐   ┌───────────────────────────┐
│ 平台 Web 前端（SPA）        │   │ Orca Cloud 桌面客户端       │
│ 工作台 / 项目 / 主机 / 权限  │   │ 工作台 · 项目视图 · 选路    │
│ 审计 / 平台设置（管控面）    │   └─────────────┬─────────────┘
└─────────────┬─────────────┘                 │
              │ REST/JSON                        │ ① REST（登录/项目/地址/凭证）
              ▼                                  ▼
        ┌──────────────────────────────────────────────────┐
        │ 平台后端 API = 注册中心 + 认证授权                  │
        │ 身份 · 项目 · 主机注册 · 证书签发 · 策略 · 审计      │
        └──────────────────────────────────────────────────┘

  桌面客户端 ──② 直连 wss://devhost:6768──────────────► 开发机 Runtime
            └─③ 直连不通：wss://relay ──TCP 转发──────► 开发机 Runtime
            （②③ 为业务数据面，不经过平台）
```

| 规则 | 说明 |
|---|---|
| 前后端分离 | Web 前端为独立 SPA 工程，只通过版本化 REST API 访问后端；前端可独立构建、发布、回滚 |
| 平台定位 | **注册中心 + 认证授权中心**：维护主机/项目注册信息，校验身份与权限，下发开发机地址（直连 + 中继）与短期连接凭证 |
| 数据面独立 | 客户端拿到地址与凭证后**自行建立链路**；直连优先，不通再经中继；平台不代理、不转接业务流量 |
| 中继定位 | 纯网络转发（TCP），打通办公网与内网；不解析 Orca 协议、不解密、不参与授权判定 |
| 管控面权限 | 主机、项目授权、下载策略、审计、平台设置属于管控面，**必须显式授予平台管理权限才能查看**；无权限时导航不出现，直接访问接口返回 403 并记录审计 |
| 同一身份体系 | Web 前端与桌面客户端共用 LDAP 登录、会话令牌、RBAC 与项目 ACL |
| 桌面客户端定位 | 承载开发体验（工作台-项目列表-项目视图）与选路；不提供主机注册、成员授权、审计等管控功能 |

## 3. 用户旅程

### J1 首次使用

1. 员工从公司软件中心安装「Orca Cloud」客户端。
2. 打开客户端看到登录页，输入域账号与密码。
3. 平台经 LDAPS 校验成功，签发会话；客户端同步 LDAP 组得到角色。
4. 进入工作台，看到自己有权限的项目卡片与列表。
5. 选择项目 → 点击「打开」→ 客户端展示选路进度 → 进入项目视图。
6. 在终端中运行 `claude`，开始与 AI 协作。

### J2 日常使用

1. 客户端保持登录态，启动后直接进入工作台（令牌有效时）。
2. 项目视图顶部显示当前线路（直连/中继）、延迟、主机名。
3. 工作区列表可切分支、新建工作区；文件浏览器只读浏览。
4. 尝试下载文件时被拦截，提示项目策略并引导申请（二期）。

### J3 管理员注册主机

1. 管理员在管理台「主机」页点击「注册主机」，生成一次性令牌（24 小时有效）。
2. 在目标开发机执行平台给出的安装命令。
3. Agent 注册成功，上报指纹、版本、监听地址、网络位置。
4. 平台记录该主机的直连地址与中继地址；客户端连接时按序探测，直连不通再走中继。
5. 管理员创建项目并绑定主机、路径、可见组。

### J4 连接故障

1. 开发者打开项目，直连探测超时，自动回落中继。
2. 若中继也不可达，展示错误面板：错误码、分步诊断、重试入口。
3. 开发者可复制诊断信息提交给管理员。

## 4. 功能需求

### FR-1 身份认证与会话

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-1.1 | 客户端与管理台均使用公司 LDAP/AD 域账号密码登录，平台后端经 LDAPS（636）执行 bind 校验 | P0 |
| FR-1.2 | 登录成功后签发短期访问令牌（默认 30 分钟）与刷新令牌（默认 12 小时）；刷新令牌可吊销 | P0 |
| FR-1.3 | 令牌在客户端存入系统安全存储（macOS Keychain / Windows DPAPI / Linux Secret Service），不落明文文件 | P0 |
| FR-1.4 | 连续 5 次密码错误锁定 15 分钟，并产生审计事件；锁定状态对用户可见 | P0 |
| FR-1.5 | 用户与组信息按 LDAP 同步（登录时增量 + 定时全量），角色由安全组映射，管理员可覆盖单个用户角色 | P1 |
| FR-1.6 | 支持主动登出、管理员强制下线、设备丢失时吊销该设备全部令牌 | P0 |
| FR-1.7 | 会话期间权限变更在下一次操作时生效（不要求重登）；权限被收回时，在**主机与平台心跳正常**的前提下，进行中的连接在 60 秒内断开 | P1 |
| FR-1.8 | 预留 OIDC/SAML 与 MFA 扩展点，一期不实现 | P2 |

### FR-2 工作台

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-2.1 | 登录后默认进入工作台，展示问候语、统计卡、最近项目、全部项目表格 | P0 |
| FR-2.2 | 仅展示当前用户有「打开项目」权限的项目；无权限项目不可通过搜索探测到；按 ID 直接访问统一返回 404，不泄露存在性 | P0 |
| FR-2.3 | 支持按项目名、仓库、主机搜索；支持按主机状态筛选 | P1 |
| FR-2.4 | 显示每台主机的在线状态与项目最近使用时间；主机离线时「打开」按钮禁用并说明原因 | P0 |
| FR-2.5 | 统计卡包含：进行中项目数、今日会话数、可用主机数、待审批下载数（二期启用） | P2 |
| FR-2.6 | 空状态（无项目）给出明确指引：联系项目负责人或管理员 | P1 |

### FR-3 项目

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-3.1 | 管理员可登记项目：名称、唯一 Key、仓库地址、目标主机、目标路径、默认分支、负责人组、可见组 | P0 |
| FR-3.2 | 登记时校验：路径在主机白名单内、路径存在或可克隆、主机在线、同一主机路径不重复登记 | P0 |
| FR-3.3 | 用户打开项目时，平台校验 ACL 并签发连接凭证，开发机验签并校验路径白名单；必要时通过托管方法 `worktree.createManaged` 在用户工作区根内创建 worktree（路径由凭证约束） | P0 |
| FR-3.4 | 项目可归档：归档后不在工作台展示，已有工作区保留只读 30 天 | P1 |
| FR-3.5 | 项目详情展示绑定主机、路径、负责人、成员数、最近活动 | P1 |
| FR-3.6 | 同一用户重复打开同一项目时复用已有会话，不重复创建工作区 | P1 |

### FR-4 开发机管理

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-4.1 | 管理员生成一次性注册令牌（默认 24 小时有效、单次使用），在开发机执行安装命令完成注册 | P0 |
| FR-4.2 | Agent 上报：主机 ID、公钥指纹、Orca 版本、协议版本、系统信息、**直连地址列表**、**中继地址/路由键**、网络位置（办公网/内网/外网） | P0 |
| FR-4.3 | Agent 每 15 秒心跳；平台 60 秒未收到心跳判定离线；离线主机上的项目不可打开 | P0 |
| FR-4.4 | 平台维护每个主机的直连地址与中继地址，并随心跳更新；实际可达性由客户端在连接时探测，探测结果用于本次选路 | P0 |
| FR-4.5 | 支持维护模式：不再接受新连接，已有会话保持；维护原因对用户可见 | P1 |
| FR-4.6 | 支持下线与吊销：吊销后该主机所有令牌与已签发凭证立即失效；已建立连接在**心跳正常**前提下 60 秒内断开 | P0 |
| FR-4.7 | 管理台展示主机公钥指纹，首次连接时客户端提示用户核对指纹（TOFU） | P1 |
| FR-4.8 | 单台主机最多承载 32 个并发连接，超出时新连接排队 5 秒后失败并提示 | P1 |

### FR-5 连接与选路

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-5.1 | 打开项目时客户端向平台申请该项目的**开发机地址集合**（直连地址列表 + 中继端点列表）、**主机 E2EE 公钥**与**连接凭证**（TTL 60 秒、一次性，绑定用户、主机、项目、工作区根、设备与设备公钥） | P0 |
| FR-5.2 | 客户端拿到地址后**自行建立链路**：先用**不携带凭证**的 TCP 预检探测直连地址（单地址 800ms，最多 2 个）；全部失败后用不携带凭证的预检探测中继节点；选中端点后才发起带凭证的 WSS 升级 | P0 |
| FR-5.3 | 平台不参与连接建立与会话传输；平台不可用时已有会话不受影响 | P0 |
| FR-5.4 | 连接建立后保持线路不变；线路故障时断开并按退避策略重连；重连必须重新申请凭证并重新选路，**平台不可用时无法重连**（已建立会话不受影响） | P0 |
| FR-5.5 | 重连采用指数退避（1s/2s/4s/8s/16s，最多 5 次），期间界面显示状态与已用时间 | P1 |
| FR-5.6 | 连接失败展示分层错误码（客户端本地 / HTTP / WSS 关闭码）与分步诊断 | P0 |
| FR-5.7 | 项目视图显示当前线路（直连/中继）与延迟，并可打开「连接诊断」页 | P1 |
| FR-5.8 | 中继不可用时直连仍可用；直连可用时不消耗中继资源 | P1 |
| FR-5.9 | 开发机在 WSS 升级期校验连接凭证（签名、有效期、主机/项目/工作区绑定、设备公钥绑定、重放），校验失败拒绝升级；通过后**沿用未修改的 Orca E2EE 握手** | P0 |
| FR-5.10 | 中继只做 TCP 转发，不解析 Orca 协议、不解密、不做授权判定；路由表由平台单向同步且只包含已注册开发机，未匹配即断开 | P0 |

### FR-7 下载管控

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-7.1 | 平台提供全局默认策略与项目级覆盖：禁止 / 审批后允许（二期）/ 允许 | P0 |
| FR-7.2 | 托管项目默认「禁止」；禁止时客户端隐藏下载、导出、拖拽到本地的入口 | P0 |
| FR-7.3 | 分层强制：主机拒绝专用下载 RPC（`files.download`/`downloadFolder`/终端产物导出）与 host-hosted 浏览器下载；受管客户端隐藏导出入口；剪贴板由客户端限制（服务端无法读取剪贴板）；任意文件读取不阻断，仅限速与审计 | P0 |
| FR-7.4 | 每次拦截与每次超阈值读取生成审计事件，包含用户、项目、路径、大小、方法、结果、traceId | P0 |
| FR-7.5 | 被拦截时向用户展示可理解的原因与下一步（提交申请，二期可用） | P0 |
| FR-7.6 | 策略变更即时生效（≤ 30 秒），并产生审计事件 | P1 |
| FR-7.7 | 二期支持审批流：申请、审批人、有效期、单次/多次、审批记录 | P2 |

### FR-8 审计

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-8.1 | 记录事件：登录成功/失败/锁定、登出、打开项目、连接建立/断开、连接选路结果、下载拦截、主机注册/离线/吊销、项目与权限变更、策略变更、令牌吊销 | P0 |
| FR-8.2 | 审计日志只追加不可修改，保留 180 天；到期归档而非删除 | P0 |

| FR-8.4 | 日志含 traceId，可与中继、开发机 Agent 上报的事件关联 | P0 |
| FR-8.5 | 导出审计日志需审计员权限且二次确认，导出动作本身记录审计 | P1 |
| FR-8.6 | 不记录终端内容、文件内容、AI 会话内容 | P0 |

### FR-9 管理台

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标 |
|---|---|
| 登录（LDAP 校验后到工作台可交互） | P95 ≤ 1.5s |
| 工作台项目列表加载 | P95 ≤ 500ms（≤ 200 项目） |
| 连接建立（连接凭证到工作区可交互） | 直连 P95 ≤ 2s；中继 P95 ≤ 3s |
| 终端输入回显（同城网络） | P95 ≤ 120ms |
| 文件目录读取（1000 项） | P95 ≤ 400ms |
| 审计查询（31 天窗口） | P95 ≤ 2s |

### 5.2 可用性与容量

| 项 | 目标 |
|---|---|
| 控制面可用性 | 99.9%（月度） |
| 中继可用性 | 99.9% |
| 规模 | 500 开发者、200 台开发机、峰值 300 并发会话 |
| 中继容量 | 单节点 2000 并发 TCP，2Gbps；至少 2 节点 |
| 故障恢复 | 单节点故障不影响新会话建立；已断会话由客户端自动重连 |

### 5.3 安全

| 项 | 要求 |
|---|---|
| 传输 | 公网/办公网 TLS 1.2+（优先 1.3）；**携带连接凭证的 WSS 升级必须 TLS（内网亦然）**；中继按 SNI 透传 |
| 端到端 | 客户端与开发机之间保持 Orca E2EE（nacl.box）；中继与网络链路不可解密。平台是主机公钥的分发者（信任根），客户端首次连接固定指纹后，平台无法在不被发现的情况下替换 |
| 凭证 | 域密码不落库、不落日志；令牌加密存储；签名密钥 90 天轮换 |
| 授权 | 默认拒绝；最小权限；权限变更在心跳正常前提下 60 秒内传播；未登记的新 RPC 方法默认拒绝 |
| 注入与穿越 | 路径穿越、命令注入、SSRF 均需防护并测试 |
| 审计 | 所有敏感操作可追溯；日志完整性校验 |
| 供应链 | 依赖锁定、构建可复现、镜像签名 |

### 5.4 合规与数据

- 不记录终端内容、文件内容、AI 对话内容。
- 审计日志保留 180 天，归档存储加密。
- 用户信息仅同步必要字段（账号、姓名、部门、邮箱、组），不做二次画像。

### 5.5 可维护性

- 客户端基于 Orca 上游同步，企业补丁独立成目录，升级冲突可控。
- 所有服务提供健康检查、指标、结构化日志。
- 配置变更无需重启（策略类）；二进制升级支持灰度与回滚，回滚 ≤ 30 分钟。

### 5.6 架构形态

| 项 | 要求 |
|---|---|
| 前后端分离 | Web 前端为独立 SPA，通过版本化 REST API 访问后端；静态资源与 API 可分别部署 |
| 管控面隔离 | 管控面接口在路由层统一鉴权，权限不足返回 403；前端隐藏入口不作为安全边界 |
| API 契约 | 使用 OpenAPI 描述，前后端以契约为准；破坏性变更需版本升级与灰度 |
| 会话 | Web 前端使用 HttpOnly + Secure + SameSite Cookie 承载会话；桌面客户端使用内存 + 系统安全存储 |

### 5.7 兼容性

- 客户端：macOS 12+、Windows 10 1909+、Ubuntu 22.04+（可选）。
- 开发机：Ubuntu 22.04/24.04、macOS、Windows；CentOS 7 通过容器运行。
- 协议：Orca 协议 v3，最低客户端协议 v2；低于最低版本拒绝连接。

## 6. 约束与假设

| 编号 | 约束/假设 | 影响 |
|---|---|---|
| C1 | 平台不具备开发机文件内容解密能力 | 内容级 DLP 不可行，下载管控为能力级 + 审计 |

| C3 | 开发机不开放公网入站 | 外网/办公网客户端访问内网开发机必须经中继；直连仅在同网段或 VPN 内可用 |
| C4 | 公司已有 LDAP/AD 与安全组体系 | 角色映射依赖组命名规范 |
| C5 | 员工电脑由公司统一管理，可安装企业内部应用 | 客户端分发走软件中心 |
| C6 | 一期不做容器化按需创建 | 开发机为预注册的常驻主机 |
| C7 | 网络延迟：办公网到内网经中继增加 20–60ms | 交互仍可接受，不在中继上做协议优化 |
| C8 | 主机与平台时钟偏差 ≤60 秒（NTP） | 凭证 `iat/exp` 依赖时钟；偏差超限校验失败并告警 |

### 8.2 非功能验收

| 编号 | 场景 | 预期 |
|---|---|---|
| AC-22 | 300 并发会话压测 30 分钟 | 连接成功率 ≥ 99%，直连 P95 ≤ 2s，中继 P95 ≤ 3s |
| AC-23 | 单中继节点宕机 | 客户端重连时优先直连，或切换另一中继节点，5 次退避内重连成功；期间新开会话成功率 ≥ 99% |
| AC-24 | 数据面抓包 + 平台日志审查 | 终端内容为密文；平台与中继日志无业务内容明文；平台只持有公钥与元数据 |
| AC-25 | 令牌泄露演练 | 吊销设备后：访问令牌 ≤5 秒失效（会话纪元、Redis 正常）；刷新令牌立即失效；主机已建立连接 ≤60 秒断开（心跳正常） |
| AC-26 | 审计日志篡改尝试与并发写入 | 记录不可修改；3 个 API 副本并发写入 10 万条后链校验通过、无分叉；篡改导致校验失败并告警 |
| AC-27 | 用户 A 尝试读取用户 B 的 worktree（正常 RPC） | 读操作允许；写入被拒（WebSocket RPC 错误 `PATH_OUTSIDE_ROOT`，非 HTTP 403）并审计；A 的凭证 `workspaceRoot` 仅指向自己的目录 |
| AC-28 | 只有 `file:read` 的用户调用 `files.write` | 主机按方法级映射拒绝（RPC 错误 `PERMISSION_MISSING`），审计记录方法与凭证权限 |
| AC-29 | 主机公钥被替换（中间人） | 已固定的指纹不匹配 → 关闭码 4433，强制中断并要求重新核对，写审计 |
| AC-30 | 凭证被复制到另一台设备使用 | 主机要求请求头设备公钥与凭证 `devicePubKey` 一致；不一致或缺失均拒绝（升级期 HTTP 401 + `x-orca-reject`） |
| AC-31 | 凭证签名密钥轮换 | 轮换期新旧 `kid` 并行验签成功；轮换后 60 天内旧公钥仍可验旧凭证 |
| AC-32 | 外网（无 VPN）用户访问管控面接口 | WAF 直接拒绝（403/404），不进入应用层；工作台与打开项目仍正常 |
