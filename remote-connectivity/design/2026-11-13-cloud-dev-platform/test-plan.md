## 1. 目的与范围

本计划把 32 条验收标准逐条映射到**真实测试用例**与**证据文件**，并明确哪些条目只能在
独立环境验证。映射只认用例里的断言，不按测试名称推断覆盖。

结论词汇：

| 结论       | 含义                                                                |
| ---------- | ------------------------------------------------------------------- |
| PASS       | 该 AC 的全部预期均有测试断言覆盖，且证据可复查                      |
| PASS(部分) | 核心路径已由测试+证据覆盖，但仍有明确未覆盖的子项（在“说明”列写清） |

## 2. 分级策略（引用 DEVELOPMENT_PROCESS §4.1）

| 级别          | 触发            | 本计划用法                        |
| ------------- | --------------- | --------------------------------- |
| L1 最小测试   | 每次改动/提交前 | 只跑改动文件与同目录邻居          |
| L2 模块测试   | 模块完成        | 单个模块的全部测试文件            |
| L3 里程碑测试 | 里程碑收口      | 按模块分批，不同时起多个 e2e      |
| L4 全量验收   | 发版前          | 单独执行，不在补验证/文档阶段运行 |

强制约束：

- 每次测试命令必须带并发上限：Vitest `--maxWorkers=N`；平台 `node --test --test-concurrency=N`。
- 本轮补验证只按单文件顺序执行；大范围 e2e 不并发拉起。
- 跑 L3/L4 前检查 `uptime`；1 分钟负载超过核数一半时降并发或等待。
- `tsc` 与 `pnpm run check:code-quality:changed` 每轮都跑。

### 7.3 node:test 超时形态门禁（静态检查）

`node:test` 只认对象形态超时（`test(name, { timeout }, fn)` / `before(fn, { timeout })`）；数值第三参或 hook 数值第二参在 Node 24 被**静默忽略**（U287/U290/U300 判例）。

```bash
node cloud-platform/scripts/check-test-timeouts.mjs               # 工作区：只报基线外新增
node cloud-platform/scripts/check-test-timeouts.mjs --from-head --check   # 已提交内容
node cloud-platform/scripts/check-test-timeouts.mjs --update-baseline     # 由当前迁移批独占执行（§2-149）
```

基线与计数：内容键 = `文件 | 形态 | sha256(被调用名 + 非回调实参，空白折叠)[:12]` + 出现次数（行号不入键）。2026-11-18 状态：基线 **78**（hook 55 + 数值第三参 23）；批 1/批 2 已迁移 194 处（258 → 78）。编辑器/格式化造成的多行重排不产生新违规；扫描器的已知不支持项见下方「已知限制」。

**已知限制**（2026-11-18；除注明外为**漏检**方向，当前语料 0 命中；跟踪于台账 U303/U305/U306/U311/U313）：

1. `v` 标志嵌套字符类（`/[[a]/]/v`）：扫描器在首个 `]` 提前闭合，两版均不支持，以 `test.skip` 显式登记（U303 ③）。
2. 标识符前夹空白/注释的点号属性（`obj . in`、`obj.\n in`、`this.#in`）：不按除法处理，后续 `test()` 可能被吞（U303）。
3. 条件语句后含引号的正则（`if (x) /it's/`）：引号帧失同步，可能吞掉后续代码（U303）。
4. 非十进制数值形态（`0x1388`、`5000n`、`1e1_0`）：曾完全漏检（Node 24 对三者作第三参均静默忽略）；**U306 已修复并归一**，修复前后扫描均 78→78（当前语料 0 命中）。
5. 同文件同超时形状共享内容键（最大 count=7）：删一处不报违规，仅输出非失败 stale key 摘要（U305 ①）。
6. 括号形式内/后加注释会**静默漏报**：`Number /*c*/ ["POSITIVE_INFINITY"]`、`Number["POSITIVE_INFINITY"] /*c*/`、`(Number /*c*/)["POSITIVE_INFINITY"]` 实测均不报（3/3）。raw 文本因注释解析失败，clean 回退已把字符串体抹掉，故回退只覆盖点号形式；当前语料 0 命中（U313 ①）。
7. 过匹配（**误报**方向）：裸 `POSITIVE_INFINITY`/`NEGATIVE_INFINITY`，以及运行时为 `undefined` 的 `globalThis.POSITIVE_INFINITY`/`global.POSITIVE_INFINITY`，实测均被判为超时特殊值并报 `numeric-special`（`SPECIAL_ACCESS` 的对象前缀可选）；当前语料 0 命中（U313 ②）。
