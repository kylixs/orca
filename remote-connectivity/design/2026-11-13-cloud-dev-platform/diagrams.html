Orca Cloud 云端开发平台 — 架构与拓扑

平台只做注册与认证授权；客户端拿到地址后自行建链；中继只做 TCP 转发。

版本 v1.2 2026-11-13 关联：requirements.md / design.md

01总体架构图

管控面（细线）负责登录、项目查询与地址/凭证下发；数据面（粗蓝线）是客户端与开发机之间的 Orca WSS + E2EE，完全绕开平台。中继仅在直连不可达时承接 TCP 转发。

业务数据面（直连 / 中继） 控制面 REST 心跳与事件上报
关键点：平台没有任何一条线承载终端或文件流量。平台 API 停机时，已建立的会话不受影响；中继停机时，直连主机不受影响。

02组件拓扑图

按进程划分职责：客户端进程内新增选路器，平台 API 按领域拆模块，开发机由 Agent 守护 Runtime 并在 RPC 分发层挂策略网关。

策略网关为什么在开发机：平台不承载流量，无法在链路上拦截导出；因此文件导出、浏览器下载、剪贴板限制必须在 Runtime 的 RPC 分发层执行，并由 Agent 上报审计。

03部署拓扑图

办公网放平台与员工终端；DMZ 只放中继（唯一从 DMZ 进入内网的点）；内网开发机不开放公网入站，通过出站心跳注册。

业务数据面 控制面 / 管理 出站心跳
网络边界：DMZ 只有中继暴露 443；内网开发机不开放公网入站。中继的出站防火墙只允许访问已注册开发机的 6768 端口，且不提供 UDP 与 HTTP CONNECT，避免成为通用内网跳板。

04打开项目的时序

失败与重连：凭证 60 秒内有效且只能使用一次；升级失败可重申请一次（failoverBudget）。断线重连必须重新申请凭证，因此平台不可用时无法重连——但已建立会话不受影响。

05关键取舍

决策选择原因与代价
平台是否承载流量 不承载（注册中心 + 授权） 平台可用性与数据面解耦，扩容成本低；代价是撤销依赖主机侧执行（≤60 秒），且无法做链路级内容检查。
选路归属 客户端自行探测 复用 Orca 现有 WSS/E2EE 栈，改动集中在选路器；代价是每个客户端都要实现超时与回落逻辑，需统一回归测试。
中继职责 纯 TCP 转发 部署简单、故障面小、与 Orca 协议解耦；代价是中继无法按用户限流或审计内容，只能靠 SNI 白名单与连接元数据。
授权执行点 平台签凭证 + 主机验签与路径校验 双层校验，客户端不可信；代价是主机需维护 JWKS 缓存、jti 重放集合与撤销同步。
下载管控 主机侧 RPC 拦截 + 客户端隐藏入口 绕过客户端仍被服务端拒绝；代价是无法阻止终端命令与截屏，需以出网管控与审计兜底。
