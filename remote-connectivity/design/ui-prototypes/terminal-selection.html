Orca Mobile · Terminal selection

Selection at cell boundaries

A 500 ms long press shows the selection overlay and the Copy / Select All menu immediately, while the finger is still down. Wide characters, emoji, combining marks, and wrapped lines map cell columns to string indices, so the copied text always equals the highlight.

Cell numbers in annotations are 0-based and refer to the bare test-vector row highlighted in each phone. Prompt, command, and history rows are context only and carry no vector coordinates.

Non-goals and mapping notes

These are explicit non-goals; a selection is not promised to survive these transitions. Pinch and rotation may clear the selection. Dragging stays on cell boundaries; v1 does not snap endpoints to words on release. Crossing through the other anchor is not a non-goal: the selection survives during drag and clears only on release at equal anchors.

Non-goal

Pinch cancels selection

Pinching the terminal calls the existing cancelSelect. The prototype does not show a preserved selection after zoom, and the implementation is not required to keep one.

Non-goal

Rotation / refit may clear selection

After orientation change or refit, state must stay consistent and the WebView must not crash. A cleared selection is acceptable; preserved selection is not a requirement.

Non-goal

No release-time word snapping (v1)

Dragging endpoints stays on cell boundaries. The release does not expand to a word boundary, because that would change the copied text. Copy must equal the highlight.

Current buffer line for the word seed

The v1 seed selects a token on the current buffer line only. Manual drag can cross lines. Horizontal pan is only reachable when the content is wider than the viewport; selection coordinates follow the pan.

Geometry

Long CJK runs use a 5-character window

Runs longer than five characters use a fixed 5-character window that is independent of tokenizer output: start = clamp(tapCharIndex, runStart, runEnd - 5), span [start, start + 5). In 中华人民共和国万岁, tap 人 → 人民共和国; tap 国 → 共和国万岁. In the 7-character run 春夏秋冬风花雪, tap 风 → 秋冬风花雪. Segmenter present or absent produces the same span. Numeric spans and term.select parameters match the rendered selection.

Geometry

Handle crossing normalizes anchor order

Both handles store a glyph-start cell anchor; the end handle is not stored as an exclusive boundary. The lower anchor becomes start = snapToGlyphStart(lower) and the upper becomes endExclusive = snapToGlyphEnd(upper). Crossing swaps the handle roles and produces an ordered span. Anchors are equal while dragging through the other handle: during drag keeps a single-glyph span; release at equal clears, and release at unequal anchors keeps the ordered span. term.select never receives a negative length. When the fixed upper anchor is a wide glyph, snapToGlyphEnd adds its full width (state 20).

Geometry

Blank / end of line is the only no-selection case

Only a blank or end-of-line cell with no token creates no selection or handles and disables Copy; Select All remains available (B20). A non-blank glyph with no token within ±8 is selected as a single glyph instead — for example an isolated & selects only & (state 21, G30). A blank cell between two tokens still selects the nearest token (B20a).

Pipeline

viewportToCell→snapToGlyphStart→cellColToStringIndex→tokenizer→stringIndexToCellCol→term.select

UTF-16 code units and cell columns advance separately. getWidth() and getChars() are the source of truth. Selection spans are end-exclusive.
