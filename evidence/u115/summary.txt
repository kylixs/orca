A. GET /install/host.sh?token=<installToken>  (wizard verbatim, no Authorization) -> 401 SESSION_EXPIRED
B. GET /install/host.sh?token=<installToken>  + Authorization: Bearer <admin>     -> 200 text/x-shellscript

Root cause: server.ts resolveToken() (line ~1289) reads ONLY `Authorization: Bearer`.
The query `token` on host.sh is the host registration token (hostTokens table), never an auth credential.
requireAuth() fails before token validation, so both script kinds are unreachable from the target machine.

Tests missed it: install-wizard.e2e "the exact command the admin copies must work as-is" then fetches the
same URL WITH `headers: auth(adminToken)` — the add-on header is exactly what the copied curl lacks.
